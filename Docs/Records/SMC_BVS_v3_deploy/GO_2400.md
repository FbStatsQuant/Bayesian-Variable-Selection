# GO_2400: production release for the 2,400-unit run (HQ, 2026-10-23 ~12:40Z)

**Decision: GO WITH CONDITIONS.** Basis: NOTS_READINESS.md (all PASS) and the independent gate review GATE_REVIEW_GO2400.md (Opus xhigh, CW), whose conditions HQ adopts in full. Do not submit the array until C1, C2 and C4 are done and recorded in STATUS.md.

## Conditions

**C1. Unit limits allow for escalation.** Escalated fits use 4× the particles and stages, and they are the hardest datasets. Truncating them would bias the results.
- L500 = 6,300 s and L1000 = 24,000 s: the brief's 3× rule applied to the measured escalated cost.
- The in-run `--hours` equals the unit limit (F5).
- Prefer TWO arrays, one per p, so p500 tasks request a short wall: 2 × 6,300 s plus margin ≈ 3 h 40 min. p1000 tasks get 2 × 24,000 s plus margin ≈ 13 h 42 min, under the 1-day limit.

**C2. Pin Sapphire Rapids nodes**, where all timings were measured. Find the node feature name with `sinfo -o "%N %f"` and use `--constraint=<feature>`. Record it in the manifest.

**C3. Stop rule.** At each poll (at most every 10 minutes, ONE ssh connection), report the counts of finished, escalated, `resource_limit`, timeout and infrastructure-failure units. HOLD the array (scontrol hold the pending tasks; never cancel running ones) and add a Request to HQ if either occurs in the first 200 finished units:
- any `resource_limit` or timeout; or
- infrastructure failures above 2%.

**C4. Finish the rerun machinery BEFORE launch:**
- `reconcile.py` must handle requeued and rerun job IDs, not only the original;
- stale locks must actually be cleared, as task.sh claims;
- submit with `--no-requeue`, so Slurm's automatic requeue cannot use up the single rerun;
- provide a tested `rerun.sh` that reruns infrastructure failures only, with the same seed.

Have a Sonnet agent review the rerun machinery before launch.

**C5. Fits stopped by the time limit form their own category** in OUTPUTS.md and in the analysis. They are never silently counted as failures. Note the asymmetry: benchmark methods got one doubled-time retry on timeout, and SMC-BVS gets none under these limits. The analysis must report it.

**Also:** correct NOTS_READINESS.md §4. Design D4 never reached its size cap (exact E|S| ≈ 2.5), and no tiny-p fit escalated. State both plainly.
