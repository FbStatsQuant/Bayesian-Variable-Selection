## Numbered findings

1. **MAJOR — The sidecar is not exactly once across checkpoint/restart.** [src/island/island_run.h:406](/home/fb31/.t3/worktrees/Bayesian-Variable-Selection/t3-091fee5d-d7c2651b2f620736/Scripts/SMC_BVS/engine_v4/src/island/island_run.h:406) (also checkpoint/load at lines 466 and 558).

   `cost_complete()` blindly opens in append mode; it neither reconciles the existing sidecar with the selected checkpoint nor recovers a committed row missing from the sidecar. Reviewer probe: stop after step 3, resume through step 9, then resume again from the same step-3 checkpoint (equivalent to losing work beyond the last checkpoint): the sidecar has 16 data rows, with steps 4–9 duplicated, while `IslandRun::cost` has 10. Separately, retaining only the sidecar prefix through step 2 models a kill after checkpoint commit but before the step-3 append: resume produces steps `[0,1,2,4,5,6,7,8,9]`, permanently omitting step 3. The existing test only exercises an orderly stop/resume with all appends present.

   **Fix:** define a durable committed-prefix protocol keyed by run identity, checkpoint generation and step. Before continuation, reconcile/rebuild the sidecar prefix from the chosen checkpoint, discard/archive uncommitted suffixes, and backfill missing committed rows. Test both crash windows, fallback to the older checkpoint, repeated submissions, and multiple resumes. If retaining all physical attempts is intended instead, explicitly define that separate stream and provide a deduplicated logical record; the present contract promises the same per-step rows.

2. **MAJOR — Checkpointed cost rows lose their finalized timing fields.** [src/island/island_run.h:401](/home/fb31/.t3/worktrees/Bayesian-Variable-Selection/t3-091fee5d-d7c2651b2f620736/Scripts/SMC_BVS/engine_v4/src/island/island_run.h:401), [src/island/island_run.h:466](/home/fb31/.t3/worktrees/Bayesian-Variable-Selection/t3-091fee5d-d7c2651b2f620736/Scripts/SMC_BVS/engine_v4/src/island/island_run.h:466) (call order at 656–658 and 737–741).

   `cost_close()` pushes the row, `save_ckpt()` serializes it, and only afterward does `cost_complete()` fill the checkpoint/check time and whole-step wall. Loading never repairs the saved version. In the probe, step 3 before/after resume changed from wall `2.64988115 / 2.58986266` seconds, check `0.01191621 / 0`, and checkpoint `0.059955413 / 0`. Thus the final binary's historical row differs from the sidecar row for the same committed step, and the checkpoint's cost disappears after resume. The PR test compares only two integer fields in historical rows, so misses this.

   **Fix:** use a defined durable completion record/two-phase protocol for the timing of the checkpoint itself, or explicitly charge it to a separately persisted segment boundary. Persist/recover all finalized row fields consistently; do not claim exact preservation while saving provisional rows. Compare every historical raw field and every emitted column against the pre-resume/sidecar record in the regression test.

3. **MAJOR — Row totals are inconsistent with island totals, and final store-check cost is unassigned.** [src/island/island_run.h:558](/home/fb31/.t3/worktrees/Bayesian-Variable-Selection/t3-091fee5d-d7c2651b2f620736/Scripts/SMC_BVS/engine_v4/src/island/island_run.h:558), [src/island/island_run.h:395](/home/fb31/.t3/worktrees/Bayesian-Variable-Selection/t3-091fee5d-d7c2651b2f620736/Scripts/SMC_BVS/engine_v4/src/island/island_run.h:395), [src/island/island_run.h:757](/home/fb31/.t3/worktrees/Bayesian-Variable-Selection/t3-091fee5d-d7c2651b2f620736/Scripts/SMC_BVS/engine_v4/src/island/island_run.h:757).

   Load restores `res.cost` but not `res.ks`, store cumulative counters or elapsed-time baselines. After the step-3 resume, row sums versus `ks` are: particle-rounds **432 / 288**, flips **460344 / 298043**, offers **44606 / 16758**, merges **11 / 6**. Historical rows account for the old segment while totals describe only the current process. Their wall sum was `23.6286909` seconds versus `ks.t_total = 13.4707885` seconds. Independently, an uninterrupted run has **sum(row.t_check) = 0**, but `ks.t_check = 0.015836117`: the final O1 check occurs after the last row is completed/appended. This omission matters precisely at the large stores O1 targets. A failed/unfinished step likewise has no closing cost row despite possibly incrementing kernel statistics.

   **Fix:** define lifetime and segment totals explicitly and persist/reconstruct the cumulative execution state (including store and timing baselines). Charge finalization/check/failure work to a defined row or segment record before serialization/publication. Require row sums to match the totals in uninterrupted, resumed, and failure runs; distinguish measured wall/work across job segments from current-process wall. Preserve O1's check on every exit.

4. **MAJOR — A short write leaves a partial JSON line which later appends cannot repair.** [src/island/island_run.h:408](/home/fb31/.t3/worktrees/Bayesian-Variable-Selection/t3-091fee5d-d7c2651b2f620736/Scripts/SMC_BVS/engine_v4/src/island/island_run.h:408).

   `fprintf` plus `fflush` detects some failures but does not commit an entire line atomically or roll a partial write back. A reviewer run with `RLIMIT_FSIZE=400` and SIGXFSZ ignored returned the expected `io_error`, but left a 400-byte sidecar: one valid header and a truncated first data row, without a trailing newline. Appending to a preexisting torn tail also produced an invalid first line (the new header was concatenated to the fragment). No parsing/repair runs on open. `fflush` also provides no durability guarantee for the checkpoint/sidecar crash ordering in finding 1.

   **Fix:** use an explicit recoverable append/commit protocol, validate the existing trailing record, and recover to the last complete committed newline before appending. If strict all-or-nothing physical lines are required, publish a replacement file by temporary-file write, fsync and rename, or use independently committed row files and materialize JSONL. A single `write`/O_APPEND alone does not make short writes or power loss transactional. Test partial writes and restart, while preserving the binary output. With distinct output paths the existing binary writer remains isolated and atomic; the sidecar's failure does not mutate the separately written island container.
