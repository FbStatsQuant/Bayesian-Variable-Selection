## 1. Result statement (advisor report; n = 1 dataset)
On one simulated AR-design dataset (n = 200, p = 10⁶, five true signals, strong signal, seed 602020001) the SMC-BVS fit (V mode, N = 2,500 particles per island, R′ = 16 islands, engine v4) completed on NOTS in **437 billed core-hours (2 h 32 min of stage time; 3 h 04 min end-to-end including queueing)** and **recovered the true support**: HPM = MPM = S₀ = {100000, 300000, 500000, 700000, 900000} (5 TP, 0 FP, 0 FN). The five true variables have posterior inclusion probability ≥ 0.9999998 and the largest null PIP is 0.107. log Ẑ = −245.107 (deterministic lower bound log Ẑ_T = −245.388). The predictive squared Hellinger distance of the HPM and the MPM equals the oracle's (0.005786); the law mixture T gives 0.006001 (+3.7%). The HPM was already found in the calibration pilot (stage 1, φ = 0.041), so this run shows that the pipeline reaches and certifies S₀ at 10⁶, not that the islands were needed to find it. One dataset: replicate statistics follow when the 20 replicates are added.

## 3. Methods notes
- **Method/engine.** Engine v4 `smcbvs4`, code `exp/P1M-engine` **2cfaa9e5** (levers 1–3 + m3, offer floor D-29, StartView, 10⁶ memory re-size); GCC 14.3.0 `-O2 -ffp-contract=off`, island kernels built for sapphirerapids. V mode with bounded calibration (tier 0, H = 512, 3 iterations = 12 diagnostic islands + pilot island), then 16 final islands (N = 2,500, G = 256; 27 bridge + 8 burn-in + 4 measured rounds), merge with local search + LS0, eval on 10,000 test rows. Data: `smcbvs4.gen/1`, AR ρ = 0.6, β = (1, −0.8, 0.9, −0.7, 0.6), σ = 1. The frozen v3 method tag (`method-v3.1.1-listpip`) is the R-core method of the 2,400-fit comparison; its link to this engine commit was **not checked here**. The pilot counts as replicate 1 only if the freeze commit reproduces 2cfaa9e5's hashes (CAMPAIGN_PLAN_1117 §3).
- **Hardware.** NOTS `commons`, Sapphire Rapids (Xeon Platinum 8468; 2 × 48 cores, 192 hardware threads per node; billing per hardware thread, so 1 core = 2 billed CPUs). Tasks: setup 48 CPUs, calibrate 96, islands 16 × 96, merge 32, eval 8. Per-user cap 1,536 CPUs.
- **Cost basis.** "Core-h" = allocated CPUs × elapsed (sacct CPUTimeRAW / 3600). The 2,400-fit rows are 1-CPU tasks billed as 2 CPUs: core-h = 2 × runtime / 3600.

## 4. Caveats (comparability)
1. **MEASURED:** pilot cost and stages (sacct), all pilot selection/evidence/predictive values (`eval.bin.json`), setup and calibration peak memory, T5 core-h, the 242 PROD-H runtimes and RSS. **DERIVED:** pilot stage-sum wall (sum of stage elapsed, slowest island, no queueing), T5 wall (46 + 594 + 153 + 167 + 30 s; the 2.21 core-h isa_check is in its core-h, not in its wall), island mean wall, log-log slopes. **INFERENCE/ESTIMATE:** merge process memory ≈ 26–34 GiB (`MERGE_MEM.md`, probe scaling); not used in the figures.
2. **Different engines and designs.** p = 500, 1000: R/C++ core v2.2.1 and v3.1, single thread, PROD-H designs (14 signals, S1–S6), median fit 9 min / 27 min wall (≈ 0.3 / 0.9 billed core-h) on the same SPR nodes; v3.1 vs v2.2.1 ratio 0.975 / 0.978 (no regression). The 10⁵ and 10⁶ points are engine v4, multithreaded (48 and 96 threads), AR strong, 5 signals. Wall times therefore are **not** comparable across engines (threads), and the core-h jump from p = 10³ to 10⁶ is not a scaling law of one algorithm.
3. **The only like-for-like pair is v4 at 10⁵ vs 10⁶** (n = 1 fit each): core-h ×10.4 (slope 1.02), stage-sum wall ×9.2. It still mixes code (T5 = 04d8d2b5 without the offer floor), calibration iterations (T5: 2 ⇒ 8 diagnostic islands; pilot: 3 ⇒ 12) and different thread counts. Calibration share: 25% at 10⁵, 31% at 10⁶.
4. **Gap at 10⁴.** No full v4 fit exists below 10⁵ yet (the 10⁴ overlap rung starts 11-19). The green stage runs use the v3 revision-D core on an S3-type design with LS0 off, tier 0 only, 16 / 8 islands, 1 core; B3 census jobs are left out (several hit `resource_limit`). WP3 10⁴ island benchmarks are islands, not fits.
5. **Memory.** Plotted peak = max process peak over recorded stages: calibration VmHWM 54.7 GiB (13 cost records). Merge 75.1 GiB is sacct MaxRSS and includes ≈ 59 GB of page cache. Eval memory was not recorded; island 27.1 GiB comes from the O2 cost records quoted in `F1M_PILOT_FIT.md` (on NOTS, not re-read). Setup `peak_rss_mb` (13,546) is read as MiB. T5's 11 GiB is the calibration peak; its setup/merge peaks were not recorded (lower bound).
6. **Merge timings are nested:** `merge_islands` 834 s lies inside `merge_tail` 1,215 s (the whole command before write); ≈ 690 s follow it. Do not add them. Calibration took 85 min against ≈ 55 min planned (3 iterations, not 2). The merge request was 80G; the driver now uses 128G.
7. PROD-H rows carry no recovery or log Ẑ (the verdict file has only `hpm_F`); T5 values are as printed (3–5 digits); stopped fits (one p = 500 `resource_limit`, 6,300 s) stay in the CSV but out of all statistics.
