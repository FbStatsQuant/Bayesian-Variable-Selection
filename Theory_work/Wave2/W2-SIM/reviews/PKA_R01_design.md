1. **Blocking — the fast path is not equivalent to complete floating-point neighbor selection.** Evidence: `W2-FAC-B/numerics/cs_core.py:101–106,126–143` examines only the minimum/maximum outside coordinate for each swap-out. Convexity justifies the maximum in exact arithmetic, but does not enumerate all neighbors tied after floating-point scoring. An omitted interior coordinate can tie the maximum and produce a lexicographically smaller model. Reproduce with `reviews/PKA_R01_scratch/tie_control.py`: at epsilon `3e-15`, n=60, p=40, start=0..29, the imported path chooses `(out=29,in=38)`, whereas enumerating all swaps with the same `P.F_stats` formula chooses `(29,30)` among 290 maximizing pairs. This is a deterministic scorer fixture, not an observed pilot divergence. Its full-set Q is positive, approximately 5.607. The pilot has 46 reported tied scans across 300 rows; these are exact equalities of computed doubles, not evidence of mathematical score ties. `check.py` reproduces P1 n=3200,c=.98,rep=0: the tie at scan 185 has two swap-outs and the complete scan agrees there, so that particular event is not a demonstrated failure. Moreover, `ties` counts only ties among the reduced candidate list and can undercount full-neighborhood ties.

   **Fix:** retain the source files unchanged, but introduce and disclose a corrected family adapter that certifies omitted candidates are strictly below the computed maximum or falls back to complete scoring when that cannot be certified. Record tie scan, selected move, tied candidates or their digest, and relevant score gaps. Recheck tied/near-tied pilot cases and outcome sensitivity before scaling. Strengthen `validate.py:99–108` to compare every selected model/move and discovery scan: equal final models, move counts, and scores within `1e-7` do not establish move-sequence fidelity. My V3 rerun passes 120 cases, with **zero ties**, so it does not cover the observed numerical regime. Higher-precision comparisons can diagnose sensitivity but must not silently replace the specified double-precision tie rule.

2. **Should-fix — the two-truth experiment does not test the two-truth L2 theorem.** Evidence: `SINGLETON_TARGET.md` and `lemmas/L2_singleton_start_swaps.md`, opening hypotheses, require all truth coefficients to equal 1. `PKA/scripts/p2_run.py:20` instead uses `(1,-.1)` for v2, and `make_tasks.py:65–76` schedules only v1/v2. That weak-signal diagnostic is explicitly requested and should remain, but truth exclusion, truth-out moves, or center/multiplier behavior in it cannot contradict L2. The design's E3/E4 discussion groups both variants as informing S1/S2/L2 and says such behavior would contradict L2. In particular, L2's residual/multiplier argument assumes the current set contains all truths, which many weak-truth pilot starts do not.

   **Fix:** add a separately seeded and labeled `(1,1)` singleton control, or explicitly exclude the two-truth theorem from the batch's claims. Keep `(1,-.1)` as its own requested diagnostic and report its truth-in/out behavior without interpreting it as an L2 falsification. Restrict theorem-specific multiplier checks to paths and hypotheses to which the bound applies.

3. **Should-fix — the recorded “early” drift tests a different time window from L2.** Evidence: `pka_lib.py:264–269` takes drift and Q/M extrema over the entire initial swap phase; `p2_run.py:40–46` doubles the move budget until a non-swap appears. L2 sections 4–5 control each fixed `ceil(C log n)` window. The first non-swap time can grow much faster than log n, so drift over that entire phase need not vanish even when L2 is correct. Conversely, an initial-swap count alone does not distinguish early truth swaps from null-null swaps. `summarise.py:142–150` foregrounds whole-phase drift and summarizes leading null swaps only by a median. The doubling loop does recover the initial phase, but it does not stop exactly at the first non-swap: the final call can include many subsequent moves.

   **Fix:** predeclare several fixed C values, including one above `1/log(2)`, and record per-window availability, whether every move is null-null, maximum center drift, Q extrema, minimum M, and first truth-out/non-swap index. Retain whole-phase statistics as separate descriptive diagnostics. Label max-center and other late-path fields as prefix-only for incomplete early runs. The `merged_miss_by_size` implication itself is sound on this grid: K is at least s0+2, and at least ell+s0+2 initial swaps preserve size, irrespective of later moves or truth inclusion. Assert those premises explicitly; interpret the flag as sufficient evidence of an LS0-only miss, never full-method failure.

4. **Should-fix — provenance is computed but never attached to run output.** Evidence: `p1_run.py:22` assigns `prov = provenance()` but neither summary nor raw rows store it (`:36–51`). P2 never calls `provenance()` (`p2_run.py:58–82`). The function already hashes the imported scorers and family scripts (`pka_lib.py:61–68`). A frozen family-script manifest is useful, but the exact separately imported ticket snapshot also matters, especially because this design explicitly depends on a recent n1 patch. The local pilot rows do not identify their actual script/scorer hashes or numerical-library versions. The design's assertion that these values are frozen cannot substitute for the values themselves.

   **Fix:** write a per-task provenance sidecar before simulation and reference its digest/run ID in every row. Include imported-source hashes, family-script hashes, Python/numpy/scipy versions, environment, exact arguments, and task ID. Archive the sidecars and new ticket snapshot hash list with the returned results. Preserve the local pilot as locally generated and do not retroactively assign it unverified current-source provenance.

5. **Should-fix — raw output does not preserve the requested per-move audit trail.** Evidence: `pka_lib.py:272–283` replaces null deletions by counts and rounds other move scores to six decimals. P1 raw output saves all move IDs but no full-precision per-move scores (`p1_run.py:49–51`). P2 raw output saves only start size and the compressed records (`p2_run.py:80–82`), losing the starting model and individual null-deletion IDs/scores entirely. This falls short of Priority 1's request for every move's out/in/tag/score and the design's claim that full move lists stay on scratch. It also obstructs investigating near ties without regenerating a numerically sensitive path.

   **Fix:** keep a complete compressed raw record on cluster scratch: starting indices, each move's index/out/in/truth tag, full-precision chosen score and gain, and tie diagnostics from finding 1. Record termination reason and scan count. Pull back compact summaries as planned, with a digest and location of each complete raw artifact. P2 needs the same complete trace for its computed prefix. Do not infer certification solely from length: `analyse_path:308` currently labels every default “full” run complete even if the reference's `10**7` move safety limit is reached (`cs_core.py:153–154`); propagate an explicit certified/limit termination status.

6. **Should-fix — deduplication silently accepts conflicting reruns and mixed schemas.** Evidence: `summarise.py:30–34,40,128` makes the last supplied duplicate win, without comparing seed, provenance, or outcomes. A rerun with changed code or a divergent path can therefore change the reported miss rate merely by changing input-file order. Reporting the number dropped does not expose the conflict. In addition, `:140` decides availability of `retained_nulls_are_top_xi` from the first row of a cell: if that row has the field, later missing values count as false; if it lacks the field, later observed values are suppressed. The supplied P2 pilot predates that field, so combining it with newer rows makes this a practical issue rather than a hypothetical schema concern.

   **Fix:** deduplicate only matching scientific records under an explicit experiment/version identity, ignoring nondeterministic timing fields. Reject or quarantine conflicting duplicates and report their keys and source files; choose any authorized replacement by an explicit policy. Validate expected seed/configuration and task coverage. For optional fields, report observed successes, observed denominator, and missing count independently of row order. Keep early/full P2 outputs separate while recognizing their intentionally shared seed when comparing them.

**Overall verdict: NO-GO for the large batch in its current form.** Resolve the complete-scan fidelity blocker and rerun targeted validation/pilots before committing cluster resources; incorporate the reporting and coverage changes above in the frozen design. Checks that did pass: the partition construction agrees with the reference in nine additional small controls; two additional DP controls agree exactly in mode, size, and score; V4 passes; all 3,420 planned distinct seed keys produce distinct seeds; and all four supplied local-pilot summary artifacts regenerate byte-for-byte. The Clopper–Pearson formula and independent within-cell bootstrap resampling are appropriate for the stated descriptive summaries. The feasible-neighborhood membership test and scans `0..min(a,m*)` cap convention agree with `bvs_core.local_search`'s scan-before-cap behavior, conditional on a faithful, certified uncapped path. The center, Q, and M definitions agree algebraically with L2 under the stated sigma=1 model; the concerns are their hypothesis and time-window interpretation. No prohibited ticket paths were opened, no cluster jobs were run, and no git state was changed.
