# R01 disposition (review: R01_review_astra.md, REJECT 4/3/6)

All 17 findings accepted. Fixes are in commit 2 on `theory/infra`. Regression scenarios are in
`tools/test_lifecycle.py` (10/10 PASS).

| # | sev | finding | disposition |
|---|---|---|---|
| 1 | FATAL | CI can delete pre-existing large files | Fixed by design. Ticket scripts never run in a working checkout. `ci/run_ci.py` `Sandbox` creates a disposable detached worktree of HEAD in a temp dir, resets it after each script (`checkout` + `clean`), and removes it at the end. Stale sandboxes left by a killed run are removed at the next start. The snapshot/restore code is deleted. |
| 2 | MAJOR | restoration not guaranteed; parent/sibling writes; cite leaves new files | Same fix: writes anywhere land in the sandbox only. Output goes to a file, not a pipe. On timeout the whole process tree is killed (a real hang from orphaned multiprocessing workers was observed and is now handled). Calibration persists after every script and resumes. |
| 3 | MAJOR | supersede dependency guard backwards; self-edges hidden | Fixed. The guard now refuses when Y depends on X (`yid in g.dependents(cid)`), refuses self-replacement, and requires X to be ACTIVE. Self-edges are recorded by `Graph` and reported as ERROR C3-self. |
| 4 | MAJOR | retraction reverts by destination/use, losing provenance | Fixed. Re-point rows record `before`, `after`, `preexisting`, `from_version` and `to_version`. A revert puts back the exact `before` item and keeps a pre-existing independent edge to Y, so that dependent is still invalidated. A dependent restored onto a no-longer-valid input becomes SUSPECT. Scenario "D SUSPECT after Y retracted" passes. |
| 5 | MAJOR | validity and supersession conflated | Fixed. SUPERSEDED-VALID claims are no longer inert, so upstream correctness changes reach them and they can become SUSPECT while keeping `superseded_by`. Retracting Y restores only predecessors still SUPERSEDED-VALID. C4 now checks every valid consumer, not only ACTIVE ones. The S1 invariant was revised to: SUPERSEDED-VALID implies superseded_by, and superseded_by is forbidden on ACTIVE/CANDIDATE/REBASE-NEEDED. |
| 6 | MAJOR | confirmation can activate an incompletely repaired claim | Fixed. Confirmation requires the destination to be ACTIVE, the versions it was proposed against, the edge to still exist with that use, and no cycle. REBASE-NEEDED is lifted only when no PROPOSED re-point remains for that dependent. |
| 7 | MAJOR | decision rules bypassable | Fixed. Coexist requires both claims ACTIVE, an incomparable/undetermined verdict, and no freeze if a headline is involved. A non-free supersede requires strict dominance (equal is refused). `status` is no longer settable via `registry.py set`. `correct-status` accepts only text verbatim at a source line. Downgrade refuses a stronger status. Approval evidence: LIFECYCLE §5.5 now separates machine-enforced checks from PR attestations. |
| 8 | MAJOR | audit misses fabricated/misattributed statuses; PROVED-CONDITIONAL | Tightened. A missing or unreadable `status_source` is an ERROR. A status found elsewhere in the file is a WARN (it was INFO). An empty status is a WARN. PROVED-CONDITIONAL is classified as strength 1. C5 adds an INFO when a checked result rests on another ticket's author-level input. Residual: matching is still whitespace/markup-normalised substring matching within ±3 lines of the stated source. Exact cell-level matching would need structured ticket reports (see the Wave 3 REPORT registry block in `templates/ASSUMPTION_MAP.md`). |
| 9 | MAJOR | hashing covers selected text, not the claim | Fixed mechanism, plus a second seeding pass. A new `premises` field (setting/hypotheses/event definitions) is hashed with the statement. A second helper pass over all 260 ticket claims applied 476 coverage corrections (spans, premises, use-level edges, kinds), validated by script. The LaTeX transcription is hashed separately (`tex_sha256`, C11) once someone compares it. |
| 10 | MAJOR | headline metadata changes the domain (POST, Thm-Poly) | Fixed. POST's span now has premises; the exact-Gram and inclusion variants are excluded from the row (scope note); A:COEF-BOUNDED was added. Thm-Poly's span excludes editorial lines and uses the new A:RELEVANCE-POLY. Convention (LIFECYCLE §1): an assumption list is a conjunction, and variants are separate clause claims. |
| 11 | MAJOR | binding/sharpness target irrelevant proofs | Flagged rows fixed. POST's bindings now point to POST's own calculation; the POST beta-min WEAKENABLE verdict is set to NONE (weaker conclusion, not weakening); the Thm-Poly LS binding is marked TO BE DETERMINED; M5(0) no longer carries A:OP. Every other binding row is marked DRAFT until a headline's strength gate confirms it (LIFECYCLE §5.5). |
| 12 | MAJOR | statement spans and dependencies not reliably seeded | Same second pass as #9, covering all 27 sampled rows and the rest. The correction pass also flagged split-needed rows (W1-GEN:L1, W1-PXN:CR, W1-PXN:Lemma-LS, W2-FAC-A:L1, W2-FAC-B:L1, S5:L1, S5:L5, X1, X6, XA:L1, S5F:L0/L1, UNI:U-LOC, C-PACK:SL1). These are listed for HQ as follow-up; splitting needs per-claim statuses the tickets do not always state. |
| 13 | MAJOR | interface/assurance obligations not enforced | Partly fixed. `consumes` P now creates a `proof:P` edge to P's bridge lemma, so retracting a bridge propagates. Promote requires `--parity-with` (or `--no-reference REASON`) and evidence-bearing `k:PASS(evidence)` gates (S4 warns on PASS without evidence). Reviewer independence and statement-version binding of gate evidence remain attestations (LIFECYCLE §5.5). |
| 14 | MAJOR | freeze assertable without criteria | Fixed. `registry.py freeze --set` refuses unless every valid headline hypothesis is settled (failed routes counted by distinct evidence) and the config names existing `last_strategy_review` / `last_adversarial_round` files. check.py raises ERROR on an unjustified `freeze=yes`. |
| 15 | MINOR | version/git reconciliation | Fixed. `narrow` owns the major bump and is followed by `rehash --bump none`. The merge-revert recipe now first prices the change on the current graph and applies propagation for later dependents in the same PR. |
| 16 | MINOR | incomparable ≠ special case; precedence; PATCH | Fixed in LIFECYCLE §5.3 (parallel theorems unless the restricted implication is recorded; explicit dispatch order) and §3 (PATCH = repaired gap; an open gap is SUSPECT or DOWNGRADE). |
| 17 | MINOR | boundary crashes reported as success | Fixed. A boundary outcome requires a `BOUNDARY-RESULT: HOLDS|FAILS` line from a completed run. A crash, import error or timeout is a FAIL. |

Not changed: the reviewer's positive findings (first-hop BFS rule, hash determinism, separation of correctness from strength).
