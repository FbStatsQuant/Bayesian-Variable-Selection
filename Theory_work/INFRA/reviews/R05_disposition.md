# R05 disposition (review: R05_review_sol.md, REJECT 6, HQ-requested narrow scope)

All six findings accepted and fixed. Regression suite: 34/34 PASS (8 new R05 scenarios incl. a real Job kill and stale vs foreign sandbox cleanup), run inside a CI Sandbox.

| # | sev | finding | disposition |
|---|---|---|---|
| 1 | MAJOR | post-Job `kill_tree` uses recyclable pids | Fixed by removal. Numeric-pid killing is gone (`kill_tree`, `descendants`, `_process_table`, `pid_alive` deleted). On Windows the Job Object is the only termination mechanism: all and only this run's processes, by kernel membership, with the process started suspended and assigned before it runs. POSIX: the session group is killed only on timeout, before the leader is reaped, so its group id cannot have been recycled; orphans of a normally exiting POSIX script are not tracked (documented limitation). |
| 2 | MAJOR | cleanup not confined: root itself, unauthenticated or foreign worktrees, owner file outside the root, global prune; test harness outside the root | Fixed. Sandboxes are only strict `sb-*` children of the root (`_strict_child` excludes the root itself). Ownership is a lock file inside the root (manifest line + exact sandbox path) held by the creator for its lifetime. Stale removal requires a strict child, a valid manifest for exactly that path, and an acquirable lock; anything else is skipped and reported. `git worktree prune` is never run. The test harness now uses the same Sandbox, with all setup inside `try`. Scenarios R05-F2: a foreign `sb-*` worktree without a manifest survives; a stale sandbox whose owner died is removed. |
| 3 | MAJOR | partial process enumeration fails open | Moot: the process-table code was removed together with pid killing (#1), so nothing decides liveness from a process list. Ownership liveness is the lock (#2). |
| 4 | MAJOR | consumes alias loses restoration | Fixed. When the destination binding already exists under any spelling (alias, ticket-local), the re-point records that exact retained item as `after`, so planning and revert compare the same string. Scenario R05-F4 (alias-spelled destination). |
| 5 | MINOR | bytecode written without `--apply` | Fixed. Every tool sets `sys.dont_write_bytecode = True` before any local import (propagate, registry, check, assemble, ingest, build_registry, run_ci, test_lifecycle). Scenario R05-F5. |
| 6 | MAJOR | `--apply` writes follow links | Fixed. One guard, `bvsreg.safe_dest`, sits on every write: registry TSVs and their temp files, events.log, DECISIONS.md, FAILED_ROUTES.md, the issues directory and each issue file. The resolved destination must be strictly inside Theory_work/INFRA, and no path component from INFRA down may be a symlink or junction; otherwise the write is refused. Scenario R05-F6. A race between check and open is out of scope: there is no adversarial concurrent writer in this setting. |

Missing regressions the review noted are added: a Job scenario (a child spawned by the script dies with the Job), plus F2, F4, F5 and F6.
