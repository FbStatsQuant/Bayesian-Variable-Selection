1. FATAL ? CI can delete pre-existing files. Theory_work/INFRA/ci/run_ci.py:61 excludes files >=50,000,000 bytes from the snapshot, but :89?96 deletes every non-snapshotted file under the script directory. Thus merely running an otherwise harmless script deletes an existing large file. Fix: distinguish the complete pre-run inventory from saved content; never delete an existing unsaved file. Prefer execution in an isolated disposable copy with explicit output collection.

2. MAJOR ? CI does not guarantee restoration. ci/run_ci.py:73?105 has no finally around execution/comparison/restoration; interruption, launch errors, comparison errors, or removed parent directories bypass/break restoration. It protects only the script directory, not parent/sibling ticket files a script can write. step_cite (:180?198) restores existing small files but leaves newly created files and directories. Fix: isolate all execution; otherwise snapshot the complete permitted write tree, restore in finally (including directories), remove only genuinely new files, fail on restoration errors, and test interruption and deletion cases. The end-of-run dirty-tree note (:371) is not restoration.

3. MAJOR ? Supersession dependency guard is backwards. tools/propagate.py:267 checks whether X depends on Y, while its error says Y depends on X. In-memory dry-run with Y.depends_on=X and Y.implies=X accepts superseding X by Y and proposes re-pointing Y's X edge to Y itself. Graph.__init__ silently discards self-edges (tools/bvsreg.py:349), hiding the resulting dependency. Fix: reject yid in g.dependents(cid), reject self replacement, and validate the proposed post-operation graph, including self-edges, before commit.

4. MAJOR ? Retraction reverses edges by destination/use, losing provenance. tools/propagate.py:339?345,388?397 rewrites every Y@use to a historical source X@use. If D originally used both X@stmt and Y@stmt, confirmation deduplicates them (:175); retracting Y removes D's genuine Y dependency as well, so D escapes SUSPECT. If X has itself been retracted, the same code re-points to dead X and computes propagation only from Y, again missing D. Fix: persist exact before/after edges and versions per operation, preserve independent obligations, validate rollback destinations, and propagate from all invalid restored inputs. Add tests for multiple sources, chained replacements, and independently invalidated predecessors.

5. MAJOR ? Validity and supersession are conflated. tools/propagate.py:50,347 excludes SUPERSEDED-VALID claims from correctness invalidation. If A uses Z, A was superseded by B, and Z is retracted, A stays SUPERSEDED-VALID; later retract B restores A to ACTIVE (:378?380), despite its invalid input. check.py:106 checks only ACTIVE consumers, so the first inconsistency is invisible. Direct suspect/retract of a superseded row also leaves superseded_by populated, violating check.py:250. Fix: track validity separately from replacement history; invalidate superseded claims too, and restore only predecessors whose validity and obligations have been rechecked.

6. MAJOR ? Confirmation can activate an incompletely repaired claim. tools/propagate.py:157?177 checks only a PROPOSED row and nonempty reviewer string, not destination validity, current source edge/version, cycles, or other outstanding rebases. Confirming one replacement clears REBASE-NEEDED even when another remains. Fix: version proposals, validate each used fact and destination against current state, record checks per use, and derive ACTIVE only after every outstanding obligation is resolved.

7. MAJOR ? Decision rules are bypassable through supported commands. tools/propagate.py:201?214 allows coexist without incomparability, validity, parity, or freeze checks; freeze is checked only in supersede (:265). Supersede checks Y but not X's starting validity, permitting a retracted X to become SUPERSEDED-VALID. Equal axes also pass the non-free branch despite the strict-improvement requirement. tools/registry.py:29,109?120 permits arbitrary status upgrades without a minor bump; downgrade (:367?369) accepts a stronger status. Fix: centralize a transition/decision validator, require a valid predecessor and strict dominance where appropriate, enforce freeze on every affected operation, and make status changes source-backed and explicitly classified. Approval can remain a human PR control, but record its evidence rather than relying on --actor text.
