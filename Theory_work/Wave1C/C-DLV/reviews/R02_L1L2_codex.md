1. **MAJOR — Deterministic cache-probing work is missing.** `Theory_work/Wave1C/C-DLV/lemmas/L1_resources.md:32` assigns only O(W + K + J) overhead per request; `:60` consequently multiplies requests by n³ + p. In `Scripts/SMC_BVS/core/cpp/v3_score.h:274-289`, both lookup and insertion use linear probing. The cache can contain 500p entries, and `same()` (`:271-272`) compares up to K indices when hashes and lengths match. A safe deterministic bound is O(p(K+1)) per request, including full-table clearing (`:284`), rather than the stated overhead. Hashes are fixed Zobrist values (`cpp/v3_util.h:102-107`); no collision-free or expected-hashing assumption is declared. These loops terminate because occupancy is at most half the slots (`cpp/v3_score.h:264-268`), but termination does not establish the advertised cost. **Required fix:** add probing, clearing, and key-comparison costs to the work envelope, or prove a tighter aggregate bound for the actual request sequence. Also charge `Start::comp` sorting (`cpp/v3_start.h:54-63`) and store comparisons (`cpp/v3_ledger.h:33-53`). Polynomial work remains plausible, but the displayed envelope is not proved by R.2–R.3.

2. **MAJOR — The final time allocation drops a term from its own envelope.** `Theory_work/Wave1C/C-DLV/lemmas/L1_resources.md:61` includes (n+p)²p log³(n+p), whereas `:107` declares only C[(n+p)p n³ log³(n+p) + p³]. The omitted term is not dominated uniformly. Take p=n⁴: the omitted term has order n¹² log³ n, while the declared expression has order n¹². This remains within a polynomial-dimensional regime. **Required fix:** retain the omitted term in the allocation, together with any corrections from finding 1, or supply a sharper deterministic analysis that eliminates it. The abstract condition `time_n >= 2(τ W̄ + τ₀)` at `:99` has the correct factor of two for `cpp/v3_runtime.h:21-26`, including its sticky stop state; the subsequent simplified allocation does not follow from it.

3. **MAJOR — The spec-only tie-aware DP has no resource proof.** `Theory_work/Wave1C/C-DLV/lemmas/L1_resources.md:26, :56` treats the enumeration cap followed by a deterministic DP as a bounded-cost component of the specified method. `Theory_work/State_of_Project/sections/02_method.tex:499-500` specifies the fallback's output but gives no state space, transition bound, or memory representation.
