## E4.1 The DP tables (`mode_dp`, START:195-226)

(i) START:200-209: for j ≤ t_b, `mb[b][j]` = max{ρ_b(U) : U ⊆ C_b, |U| = j} and `arg[b][j]` = the nonempty set of
codes attaining it (every size-j code is visited, by (H1⁺); the first visit sets the maximum since ρ > −∞).
For j = 0: `mb[b][0]` = ρ_b(∅) = 0, `arg[b][0]` = {0}.
(ii) START:211-219: `M[0][0]` = 0, `M[0][k]` = −∞ (k > 0), and for b ≥ 1,
`M[b][k]` = max over j ≤ min(t_{b−1}, k) with `M[b−1][k−j]` ≠ −∞ of v(b, k, j), where v(b, k, j) := `M[b−1][k−j]` +
`mb[b−1][j]` (for j = 0 the code adds nothing, and `mb[b−1][0]` = 0, so the formula is uniform). By induction on b:
  `M[b][k]` = max{Σ_{i<b} ρ_i(U_i) : U_i ⊆ C_i, |U_i| ≤ t_i, Σ_{i<b}|U_i| = k}  (−∞ if no such family).      (4.1)
In particular `M[J][k]` = max{Σ_b ρ_b(S ∩ C_b) : |S| = k} for 0 ≤ k ≤ K (any S with |S| = k ≤ K has
|S ∩ C_b| ≤ t_b), and −∞ iff k > p.
(iii) START:220-224: `vbest` = max_{0≤k≤K}[λ(k) + `M[J][k]`] = max_Ω f, and `kbest` is the smallest maximising k
(λ(0) and `M[J][0]` = 0 are finite, so `kbest` ≥ 0).

**Definition (tight path).** A sequence (j_J, …, j_1) with r_J := `kbest`, r_{b−1} := r_b − j_b, such that for every
b: j_b ≤ min(t_{b−1}, r_b), `M[b−1][r_{b−1}]` ≠ −∞ and v(b, r_b, j_b) = `M[b][r_b]`; and r_0 = 0. A **tight set** is
S = ⋃_b decode_{b−1}(c_b) for a tight path and codes c_b ∈ `arg[b−1][j_b]`.

**Claim T.** (1) Every tight set is a maximiser of f on Ω. (2) A tight path exists; more precisely, from every (b, r)
with `M[b][r]` ≠ −∞ there is a sequence of tight edges down to (0, 0).
*Proof.* (1) |S| = Σ_b j_b = `kbest` − r_0 = `kbest` ≤ K, so S ∈ Ω. ρ_{b−1}(c_b) = `mb[b−1][j_b]`, and telescoping
the tight equalities, Σ_b `mb[b−1][j_b]` = `M[J][kbest]` − `M[0][0]` = `M[J][kbest]`. Hence
f(S) = λ(`kbest`) + `M[J][kbest]` = `vbest` = max_Ω f. (2) If `M[b][r]` ≠ −∞ with b ≥ 1, the maximum defining it is
attained at some admissible j, which is a tight edge to (b−1, r−j) with `M[b−1][r−j]` ≠ −∞; iterate. At level 0 only
`M[0][0]` is finite, so the path ends at (0, 0). ∎

## E4.2 The enumeration path (`start_mode`, START:271-302)

`rec(b, r)` (START:281-300) is called first at (J, `kbest`); at (b, r) with b ≥ 1 it follows exactly the tight edges
(START:293-296: j ≤ min(t_{b−1}, r), `M[b−1][r−j]` ≠ −∞, v = `M[b][r]`) and, for each, every code of `arg[b−1][j]`
(START:297); at b = 0 it accepts only r = 0 and then forms the sorted index set of the chosen codes (START:283-288).
So every accepted leaf is a tight set. By Claim T(2) and induction, every node (b, r) visited has `M[b][r]` ≠ −∞ and
therefore at least one tight edge and (arg nonempty) one code; hence the first depth-first descent reaches an
accepted leaf. `trunc` can become true only at an accepted leaf (START:290), so at least one leaf is accepted before
any truncation, `have` is true and `bestS` is one of the accepted leaves (START:289). Hence:

**(E4-a)** `res.S` as set at START:302 is a tight set, hence (Claim T(1)) a maximiser of f on Ω — whether or not the
enumeration was truncated. (This is N3-code (a) for the routine on main.)

## E4.3 The fallback (`mode_tie_dp`, START:237-270), used iff `trunc && tie_dp` (START:303)

State: disjoint index sets IN, OUT stored as per-block bit masks `inm[b]`, `outm[b]` through `st.blk`, `st.pos`
(START:264; correct by (H1⁺)). `allowed[b][j]` = [some code of `arg[b][j]` contains `inm[b]` and avoids `outm[b]`]
(START:242-246). `feasible()` (START:249-260) computes `reach[b][r]` = [there is a sequence of tight edges from (b, r)
to (0, 0) all of whose block sizes are allowed] and returns `reach[J][kbest]`. Since IN/OUT constraints are per block,
  `feasible()` is true ⇔ there is a tight set S with IN ⊆ S and S ∩ OUT = ∅.                                (4.2)
**Invariant:** after indices 0, …, i−1 have been processed, IN ∪ OUT = {0, …, i−1} and (4.2)'s right side holds.
*Initially* IN = OUT = ∅ and a tight set exists (Claim T(2), arg nonempty), so the check at START:261 passes.
*Step i* (START:263-268): i is tentatively put in IN; if `feasible()`, it stays (START:266). Otherwise i is moved to
OUT (START:267); the tight set S that witnessed the invariant before the step has IN ⊆ S, S ∩ OUT = ∅, and i ∉ S
(else it would witness feasibility with i in IN), so it witnesses the invariant after the step. *At the end*
IN ∪ OUT = {0, …, p−1}, and a tight set S with IN ⊆ S, S ∩ OUT = ∅ exists, i.e. S = IN. The returned vector is IN in
increasing order (START:266, 269).

**(E4-b)** The set returned by `mode_tie_dp` is a tight set, hence a maximiser of f on Ω.
