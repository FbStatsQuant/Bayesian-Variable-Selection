## Proof checks

**E4.1 / (4.1) / Claim T.** Verified. Only `logprof[b].size()` is read, and its required value is t_b+1. `logprof` values do not enter mode selection. For each j<=t_b there is a size-j subset, so finite real table entries make arg nonempty. Size zero has exactly code 0 and value 0; skipping the addition for j=0 therefore agrees with the stated recurrence in exact arithmetic. A block larger than K needs only sizes through K; its larger codes are never read. An empty block has the single size-zero choice. K=0 leaves the unique empty set. If K>p is admitted, sizes k>p have M[J][k]=-infinity and are skipped. In particular lambda(0)+M[J][0] is a finite real and strictly exceeds the initial -infinity, so kbest>=0. The proof should be understood to use lambda(0)'s finiteness as well as M[J][0]'s finiteness.

The finite maxima give a tight outgoing edge from each finite node. Repeated descent ends at the only finite level-zero node, (0,0). Telescoping is legitimate because every node on the selected path is finite, so no subtraction of infinities is involved. Decoded choices from disjoint blocks give cardinality kbest. This proves both parts of Claim T.

**E4.2 / first accepted leaf.** Verified. `trunc` begins false and only changes after constructing a valid leaf, incrementing count, and updating bestS/have. Every visited finite node admits a tight edge with a nonempty arg list. Therefore the first descent reaches an accepted leaf before truncation. At kbest=0 that leaf is the empty model, but it is initialised and accepted, not a failure sentinel. At J=0 the partition condition forces p=0, and rec(0,0) directly accepts the empty model. J=0 with p>0 violates encoding. With tie_dp=false, even cap<=0 would accept one leaf before truncating; the lemma appropriately does not claim these caps. With tie_dp=true, all cap<2 calls throw before mode_dp. Every bestS assignment comes from a tight leaf, including the final one retained when truncation occurs.

**E4.3 / (4.2) / greedy invariant.** Verified. At level b, the relevant block is b-1 throughout `allowed`, predecessor reachability, and `mode_tight`; there is no index shift error. `reach[0][r]` is reset each call, and all higher rows are overwritten in ascending b, so no stale reach value is used. The `!ok` loop condition merely short-circuits an existential disjunction after a witness is found. `refresh(b)` runs after every tentative inclusion and after every rejected inclusion is turned into exclusion; other blocks' masks and allowed rows are unchanged.

Per-block consistent codes can be chosen independently along a tight path, proving both directions of (4.2). In the failed-inclusion case, let IN_old/OUT_old denote the pre-step masks. Any old witness containing i would witness feasibility for IN_old union {i}, contradicting the failed test. Thus the old witness omits i and survives the new exclusion. The proof's phrase “has IN subset S” at that point must mean IN_old, not the tentative mask; this is clear from “before the step.” At termination the partition of all indices into IN/OUT forces the surviving witness to equal IN. Pushes occur once, at increasing i, precisely on successful inclusions, so the returned vector is IN in increasing order.

The fallback needs D.p to cover precisely all internal indices and blk/pos to map them into the actual blocks at distinct valid bit positions. These are supplied by H1+. Enumeration does not use these inverse maps, but the fallback and engine comp do. Code order is irrelevant to the maximiser property: the inherited increasing-code convention is sufficient and stronger than necessary. Permuting a complete per-size list changes enumeration traversal but cannot make a returned tight set nonoptimal. Entries for sizes above K may be NaN; no such entry is read. NaN or infinite entries at a required size, or nonfinite prior entries, are outside the real-table hypotheses; this is not a theorem about defensive handling of invalid tables.

## Numerical falsification attempt

Compiled the actual production v3_start.h standalone using g++ with `-O2 -std=gnu++17 -D_USE_MATH_DEFINES -msse2 -mfpmath=sse -ffp-contract=off` and the production cpp include directory. The temporary executable was confined to R05_scratch and removed after use. No Scripts file was edited.

A self-contained C++ driver used mt19937 seed 20261109 for 12,000 instances: p in 0..10, K in 0..p+3, arbitrary assignments of indices to ordered blocks (including empty blocks), and finite required table/prior entries drawn from integers -2..2, with rho(empty)=0. Larger-than-K table entries were NaN. Every third instance used all-zero required block entries and a prior rewarding one randomly chosen feasible size, creating many exact ties. For p=0 the number of empty blocks included zero. build_start constructed the profiles/codes; inverse maps were filled from the generated blocks. These tests deliberately include extensions outside N3's narrower inherited domain.

For each instance, brute force enumerated every feasible subset and computed its direct production log_gamma0. The driver checked both tie_dp values at caps 2, 3, and 1,000,000, plus tie_dp=false at cap 1. It checked attained maximum and, for the first six calls, smallest maximising size; for tie_dp=true it additionally checked the lexicographically smallest optimum. All relevant sums are small integers exactly representable in binary64.

Results: **84,000 calls; zero failures**. Among the cap-2/cap-3/cap-1,000,000 calls, **7,301 truncated calls with tie_dp=false** and **7,301 truncated calls with tie_dp=true**, the latter all using the fallback. No empirical counterexample was found. This is supporting falsification evidence, not a replacement for the proof or a claim about arbitrary binary64 tables.
