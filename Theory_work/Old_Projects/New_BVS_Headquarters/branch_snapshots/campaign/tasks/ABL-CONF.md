# ABL-CONF: confirmatory start test (block start vs singleton factors vs prior start)

**Why.** The method meeting (MEET-v31, `theory/MEET-v31:theory_campaign/MEET-v31/ITEM1_ABL_START.md`) kept the block (local-to-global) start but, under its pre-registered rule, may make **no** cost or accuracy claim for it: the rule's "> 1 nat between arms" clause made all 9 complete designs inconclusive, because the prior-start arm was far off on every design. Descriptively (12 designs × 1 seed), the singleton start B matched A's log Ẑ within 0.24 nats but cost more (sometimes > 4 h vs 10–28 min), and the prior start C underestimated log Z on 12/12 designs. This run is the confirmatory paired test the meeting named (MINUTES §3, §7 item 12). It licenses or refuses two paper claims:
- **Claim 1 (cost):** "at equal accuracy, the block start costs less than singleton factors";
- **Claim 2 (accuracy):** "at equal declared budgets, the prior start underestimates the evidence and is less accurate".
It is **not** a method question: the block start ships whatever this shows. Felipe approved the run (2026-11-03).

**Design (fix all of this in `PREREG.md` and commit it BEFORE any new fit runs).**
- Arms A (production block start), B (singleton factors × capped size prior), C (capped prior start), exactly as in ABL-START; everything else identical.
- Designs: p = 500, at least one favourable design and at least two correlated/masked designs (suggested: S1 r001 c100, S4 r001 c100, S5 r001 c100); same datasets for all arms.
- Seeds: 10 method seeds per design (Felipe's limit is 10–20), listed in PREREG, none equal to the study seed. Pairing is by (design, seed).
- **Per-fit wall cap:** declared before the run (suggested 60 min). A capped fit is a delivery failure: it counts against its arm for cost, is reported, and is excluded from accuracy comparisons only in the pairs where it failed (say how pairs are handled).
- **Reference, fixed in advance and independent of the test fits:** per design, a long reference built from fits with reserved seeds (e.g. a pool of ≥ 8 independent arm-A fits, Ẑ-weighted), and state its own error (spread / √K). Also say how you guard against the reference favouring arm A (e.g. check the reference against a pool of reserved arm-B fits on the favourable design, or report the A-vs-B comparison both against the reference and head to head).
- **Metrics per fit:** wall time, total score evaluations (calibration and final separately), rebuilds, tier, status; log Ẑ error vs the reference; island log Ẑ SD; max and mean |PIP − PIP_ref| for both PIP rules; HPM = best known.
- **Decision rules (one per claim), written as code** (`scripts/apply_rule.*`), with paired sign tests or paired-difference intervals per design and an overall rule (e.g. "claim licensed iff it holds on every design at the stated level"). One failing arm must not be able to make another pair's comparison vacuous: score each pair of arms against the fixed reference.
