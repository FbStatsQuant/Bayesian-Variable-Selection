The R entry point is `smcbvs_study_fit(case, scale, study, outroot, run_id)`, after sourcing `adapter.R`. It runs exactly one dataset/scale, loads `../core/v3.R`, and calls only `v3_fit(X, y, method_seed, allocation=...)`. Production `case` accepts `p0500_S1_r001` or `p0500_S1_r001_c100`; `scale` accepts `c100`/1 or `c050`/0.5. The CLI uses scale keys:

```sh
Rscript code/study/run_case.R --case p0500_S1_r001 --scale c100 \
  --study "$HOME/smcbvs_v3_deploy_20261022/C_ops/study_inputs" \
  --outroot "$HOME/smcbvs_v3_deploy_20261022/C_ops/fit_outputs" \
  --run-id FROZEN_RUN_ID --mem-gb 6 --hours 24
```

Root runs the current build and validation on Owls (R 4.6.0, GCC 11.5.0), under nice19 and the shared resource caps. Root owns snapshot creation, allocation, environment, persistent process launches and RUNS/ledger records. C owns assessment launches (r1..10, 240 fits); the lead selects the eventual run backend under BRIEF Amendment 2 and R-4. Paths above are examples for C to adapt to its copied input tree, not executed commands. Root checks shared-machine load/memory and total resource caps before launches. Adapter compilation/package loading is outside `runtime_s`; the whole core fit and output validation are timed. Match `--mem-gb`/`--hours` to the declared process allocation (A uses at most 6 GiB). The adapter has no method tuning switches. `--core-dir` locates the production snapshot; `--manifest` selects an inputs-manifest copy within `STUDY/manifests/`. Other inputs are constructed from the validated ID. Dev cases require `--development`, `dev_` IDs, a separate dev input tree, and dev seed bases. Cases/scales are tied to IDs rather than process indices.

Input validation checks the saved RDS SHA before deserialization, dataset/design/seeds against both the ID and manifest, X/y/fold hashes, and the selected scale. SHA-256 array bytes exactly reproduce benchmark `common.R`: `writeBin(as.double(as.vector(x)), raw(), endian="little")`, with `serialize=FALSE`. The fit receives no fold vector, truth or other response scales. Both row hashes refer to the stored inputs before core standardization. Production seeds use bases 1410000/1510000, dev 2410000/2510000; method seed is data seed + 4000000 at both scales.

Outputs are `results/RUN/pPPPP/CASE/SMCBVS.{rds,csv,sha256,done}`. A per-unit directory lock prevents concurrent writers; stale locks require operator inspection. `.done` is last. Resume skips only after checksums, requested run ID, fixed `method_id="SMCBVS"`, both rule IDs, source hash, policy hash, normalized allocation hash, manifest hash, all input hashes, case and seed validate. A valid saved unit has immutable identity: changing allocation, source, policy or inputs requires a new run ID and preserves the historical output. Copying or aliasing a completed unit from another run is rejected; the error names every mismatched identity field, and all four files are retained unchanged. Failed rows are complete/auditable units and are skipped on resume; deliberate retries also use a new run ID. Corrupt/incomplete outputs may be repaired in place. v2.1 (A-CODE F3): an R-level memory-allocation error is recorded like any other R error from the fit: native `adapter_error`, both rules `failed`, the error text verbatim, and `.done` written, as the benchmark's outer tryCatch records it. A scheduler kill (out-of-memory, node failure, wall time) leaves no `.done`; the runner then classifies it. Exit 0 means rows saved/skipped without failed rules; 2 means a saved method/rule failure; 1 means infrastructure/input/configuration failure.

`record$fit` is the entire native core return, including every nested diagnostic/index map the core supplies. Adapter does not filter it, recompute scores or manufacture missing evidence/stages. `record$pip` and `pip_primary_original` are length-input-p vectors named by original indices; dropped columns get zero only if retained primary PIPs were computed, including on failed fits. Unavailable PIPs stay NA. Successful MPM is checked against strict `>0.5`; failed returned MPM is retained for audit, or derived from supplied primary PIPs if absent. Supports are sorted original 1-based indices. Any failed rule's HPM/MPM goes into `support_audit`, with study support/k NA; native fit/partial evidence remains intact. Malformed output becomes `adapter_error`, an adapter extension to the eight native statuses; the raw return and independently valid audit outputs are retained. `tp`/`fp`/`fn`/`exact`/`error_type`, all active-variable and null-PIP scoring fields remain NA.

`RULINGS_LEAD.md` R-1 supersedes the earlier OPEN mapping. The fixed adopted policy is `smcbvs_r1_policy()` (`id="R-1-20261022"`): hpm has role `primary`, pip05 has role `S0`, and `converged` is always NA. Native `exact`/`completed` map to `ok`, or `warning` iff an R warning/message was captured. Every other native status, including unexpected study `y_constant`/`no_predictors`, maps to `failed`. The adapter never emits `timeout`/`not_run`; reconciliation owns those. Both row fold fields are NA; validated fold provenance remains in `record$case`/`record$input`. Method seed remains data seed + 4000000.

Diagnostics are independent of status and selection on both rows, including failed fits. A failed final-check summary, low empirical ESS, unconverged grid, or any archived native local-limit check sets `diag_flag`; missing/NA checks do not. Local-limit inspection includes failed final searches and calibration triggers/searches across tiers. Final E1/E2/E3 codes refer only to the failed final summary, never calibration E triggers. Escalation, cut groups, near-tie truncation, positive numeric `forced_pilot_steps` counts, exact branch, false local certification and global certification are informational codes only. Warnings/messages retain their exact `conditionMessage()` text, including trailing newlines; ordered separate vectors are saved in RDS. Native explanatory `fit$message` text alone does not set `warning`.

The R API `policy` argument and CLI `--policy RDS` accept only an identical copy of the fixed R-1 policy, in production and development. Contrary policies are refused before creating a result. Historical unresolved snapshots/results stay frozen and require new run IDs for R-1 execution. Full ordered CSV columns, RDS fields and nested native structures are documented in [SCHEMA.md](SCHEMA.md). `smoke/test_adapter_contract.R` reuses the existing fixture core and covers R-1, audit preservation, conditions, numeric counts and failed nested searches. Root must run it on Owls in an empty evidence directory; these edits were not executed locally.

The snapshot hash covers production R/C++/Makevars plus all study R/Markdown files, including SCHEMA.md; each file hash and source path is retained. Root must retain that frozen snapshot. RDS also saves input manifest row/hash, actual allocation, command, warnings/messages/error, timestamps, session/library/compiler/module/thread/Slurm details and PID. No scoring or truth access occurs here.
