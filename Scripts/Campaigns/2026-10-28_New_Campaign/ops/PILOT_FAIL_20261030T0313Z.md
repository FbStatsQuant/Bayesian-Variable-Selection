# LOWP pilot 20261030T0313Z: early STOP at P0a. Root cause and bundle findings (OPS-4, 2026-10-30)

**Verdict: bundle/design issue, not environment or staging. Not resubmitted.** Needs a CONF-2b fix and a narrow Sol check (HQ routes).

## What happened
Jobs 2467487–2467498 were submitted at 03:14Z with every gate passed. At 03:14Z `s0_verify` (P0a, job 2467488) stopped with **MISMATCH (exit 1)** after 6.6 s on bb3u16c1 (Xeon 8468, R 4.5.2, FlexiBLAS/OpenBLAS). ## Root cause (B1, blocking): P0a demands bit-identical regeneration across platforms, which is impossible
- Not staging: `code/lowp/R/lowp_generate.R` is unchanged since 2026-10-28 21:17, before the seal (2026-10-30 00:13Z, R 4.4.1 on Windows). Locally, X of p0020_S1_r001 regenerates to `6a3a7b8e…`, equal to the manifest.
- Not BLAS: a step-by-step probe (`ops/scaffold/p0a_probe.R`, run on the laptop and on loginx2) shows the **raw normal draws** `z = rnorm(n*p)` already differ for the same seed and `RNGkind("Mersenne-Twister","Inversion","Rejection")`: laptop `d8cbcf23…`, NOTS `b8917e1f…`. `eps` differs too. This holds under FlexiBLAS OPENBLAS **and** FLEXIBLAS=NETLIB, and for S1, where Sigma = I so `chol` and `%*%` are exact. The source is the inversion `qnorm` path, i.e. platform libm `log`/`sqrt` between R 4.4.1/Windows (UCRT) and R 4.5.2/Linux (glibc), not BLAS. (`chol` additionally differs between NOTS backends, but that is secondary.)
- The size is last-bit only (`ops/scaffold/p0a_magnitude.R` on the 6 pilot datasets, regenerated on NOTS vs the sealed copies): `eps` max relative difference ≤ 5.5e-16 (1–3 ulp, ~50 % of elements); X max absolute 1.3e-15 (relative ≤ 2.9e-12 after `scale()`); Y ≤ 3.6e-15; signal ≤ 3.6e-15; **foldid identical**.
- The seal header's claim "float64 hashes … are independent of R version and platform" is therefore false. As written, P0a can never PASS on NOTS against a laptop seal. No environment setting fixes it, so OPS did not resubmit.
- The pilot's fits use the **copied** sealed files, not regenerated data, so the fit inputs are canonical. P0a's job is to prove the generator/seal is right. For CONF-2b / HQ to choose (OPS proposes nothing binding):
  (a) P0a compares regenerated arrays with a stated tolerance (for example relative ≤ 1e-11, or n ulps) plus exact checks for the integer `foldid`, the seed fields and the file SHA-256 of the staged copies;
  (b) re-seal on NOTS (R 4.5.2, Linux) so that regeneration and the seal share a platform. This changes the canonical source: an HQ decision, with a new audited seal, manifest and transfer;
  (c) regenerate locally as the gate (the laptop is the sealing platform) and keep only the transfer/file-hash check on NOTS.

## B2 (should-fix): the wave-unlock finalizer fails whenever the lock never ran
`truth_wave.sh unlock` is passed the pre-lock hash folder. When `s0_lock` was cancelled (any P0a/P0c STOP), `pre_truth.sha` does not exist, `cmp` fails and the unlock reports `SHA256_AGAINST_PRELOCK DIFFERENT` → `WAVE_UNLOCK_FAILED` (exit 1), although the trees were never locked and are intact. Here `recover_truth.sh` gave RECOVERED (exit 0; 1,200 + 60 files, 755/444), and an OPS check of all 1,260 staged truth files against `STAGED_SHA256.txt` gave **TRUTH_SHA_OK**. Proposed fix: if no pre-lock list exists, report `LOCK_NEVER_RAN` and verify the open state plus the hashes against `STAGED_SHA256.txt` instead of declaring DIFFERENT.

## B3 (minor): cleanup_pilot.sh cannot verify itself on NFS
Run as `bash HOME/runs/<PID>/code/lowp/pilot/cleanup_pilot.sh`, bash holds the script open while it deletes its own folder. NFS silly-renames it to `.nfsXXXX`, so `rm` reports "Directory not empty" and the script prints `CLEANUP UNVERIFIED: rm-failed residue-found` (exit 1). After exit only 4 empty directories remained. OPS removed them with `rmdir` and verified (`CLEANUP_VERIFIED_MANUAL`). Proposed fix: the clean-up copies itself to the scratch temp folder (or OPS runs a copy from scratch) before removing `runs/<PID>`, or JOB.md §11 says to run it from a copy.

## OPS-side fix (done)
The local waiter `ops/scaffold/pilot_monitor.sh` was broken. With an empty squeue, `sed '1,/^===$/p'` ran to EOF and counted sacct rows as queued, so it polled a finished run for 40 min without waking OPS. v2 separates the sections with awk, treats COMPLETED/FAILED/CANCELLED*/TIMEOUT/OUT_OF_MEMORY/NODE_FAIL/PREEMPTED/BOOT_FAIL/DEADLINE as terminal, exits 3 at once on any FAILED/TIMEOUT/OOM/NODE_FAIL, and takes the job ids as an argument.
