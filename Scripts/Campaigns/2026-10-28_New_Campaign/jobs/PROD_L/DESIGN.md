## 0. Principles

1. **Reuse the pilot.** Every pilot file that does the same job is copied into `B` and changed minimally. `B/REUSE.md` lists every reused file: source path, source sha256, and a one-line diff summary (or "unchanged"). Function names of `PILOT/slurm/common.sh` (`pilot_init`, `timed`, `pilot_modules`, `pilot_blas_single`, `pilot_require_frozen`, `pilot_finish`, GNU-time resolution) stay as they are.
2. **One staging, one run folder.** Everything staged lives in ONE folder `HOME_ROOT/runs/<RID>` with `RID = <STAMP>_lowp_prodL` (STAMP = `YYYYMMDDTHHMMZ`). Nothing shared is overwritten. Logs: `SCR_ROOT/logs/<RID>/`. Results: one folder per piece, `SCR_ROOT/results/<STAMP>_lowp_<piece>/p0020|p0030/<unit>/`, pieces `enum20 enum30 smc smcrep` (and later `bench`). Caches/TMPDIR: `SCR_ROOT/runs/<RID>_cache`, `SCR_ROOT/runs/<RID>_tmp`.
3. **Frozen code.** SMC = `code/core/v2_2_1` verified against `code/core/v2_2_1.SHA256SUMS` (manifest sha256 `d880afdb…13e1`, 27 files) at staging, at every submission and in every SMC task (`frozen_check.sh`, unchanged).
4. **Truth separation.** The staged study copy `RUN_HOME/study` = the WHOLE sealed study (`manifests/`, `inputs/` 1,200, `truth/` 1,200, `dev/{inputs,truth,manifests}`). Fits read `--study RUN_HOME/study` (inputs and manifests only). Both truth trees are mode 000 (verified) for every fitting wave.
5. **D38 approval-safe tooling** for every agent working on this bundle: Edit/Write for edits; absolute paths; no `cd … &&`; no `rm` globs; no heredoc edits in Bash; one simple command per Bash call; scripts run by absolute path. Scripts themselves may use any shell constructs.
6. **Local CPU cap:** at most 6 concurrent R processes on the laptop (tests included).

## 2. Unit commands (production CLIs, unchanged)

- enum: `Rscript $ENUM_DIR/run_enum_dataset.R --dataset <id> --study $STUDY --outroot $SCR_ROOT --run-id <STAMP>_lowp_<piece> --threads <T> --core-dir $CORE_DIR` (T = 4 for enum20, 16 for enum30; `OMP_NUM_THREADS=T`, `LOWP_ENUM_CACHE=$CACHE_ROOT/enum`, `LOWP_CORE_DIR=$CORE_DIR`).
- smc / smcrep: `Rscript $V221_DIR/study/run_case.R --case <dataset> --scale <scale> --study $STUDY --outroot $SCR_ROOT --run-id <STAMP>_lowp_<piece> --core-dir $CORE_DIR --mem-gb 2 --hours 4 [--repeat m]`.
- P5 rerun: the same smc/smcrep command plus `--p5-retry`, with the PRIMARY allocation `--mem-gb 2 --hours 4` (the adapter doubles it).

The SMC adapter refuses a unit whose `.lock` directory exists ("stale locks require operator inspection"); the enumerator treats a lock older than 10 min as stale.

## 3. Batch deadline rule (D47.2; Sol finding 5): `B/batch_runner.sh`

Every multi-unit array task (enum20, enum30, smc, smcrep, resubmissions, P5) runs its units through `batch_runner.sh`, sourced or called by the sbatch script after `pilot_init`/`pilot_modules`/`pilot_blas_single` (and `pilot_require_frozen` for SMC).

Inputs (environment, set by the sbatch script from the driver): `PIECE`, `UNITS_FILE` (the `units.tsv`-format rows of this task, or a resubmission list in the same format), `TASK_ID` (array index), `PRODL_WALL_S` (the task's Slurm `--time` in seconds; the driver passes the SAME value it used for `--time`), `UNIT_BUDGET_S`, `P5` (0/1).

Per-piece constants (one table in `prodl.env`, used by the driver for `--time` and by the runner):

| piece | Slurm `--time` | `UNIT_BUDGET_S` (hard `timeout` per unit) | why |
|---|---|---|---|
| enum20 | 01:00:00 | 300 | unit ≈ 2 s (max 6.8 s measured) |
| enum30 | 00:45:00 | 600 | unit ≈ 27 s at 16 threads |
| smc, smcrep | 05:00:00 | 14,700 = 4 h core guard + 300 s write margin | core per-fit guard `--hours 4` |
| p5 | 09:00:00, one unit per task | 29,100 = 8 h (doubled) + 300 s | |

Rule, applied before EVERY unit (the first one included):
- `T0` is captured before modules. Obtain scheduler end from numeric `SLURM_JOB_END_TIME`, otherwise from `squeue -o %e` parsed by `date -d`. Production refuses all units as deferred with `no_scheduler_end_time` if neither works; only local tests may use script time. Deadline is `min(T0 + PRODL_WALL_S − START_SLACK_S, end − 60)`; records include end source and epoch.
- `NEED_S = UNIT_BUDGET_S + KILL_GRACE_S (60) + COMMIT_MARGIN_S (120)`.
- Start the unit only if `now + NEED_S ≤ D`. Otherwise this unit and every later unit of the task are recorded `deferred` (never started) and the task stops launching.
- A started unit runs as `timed <piece> <unit> <threads> timeout --signal=TERM --kill-after=60 <UNIT_BUDGET_S> <cmd…>`. This protects the ordinary wall budget; cancellation, OOM, node failure and other external interruptions can still stop writes.

Unit records ("ledger") live under `LOG_RUN/ledger/<piece>/<unit>/`. Start records use noclobber; existing starts refuse execution. End and deferred records use temporary names and rename. Files are named by `JOB_TAG = <array job id>_<task id>` (local: `local_<task>`):
- `<JOB_TAG>.start`: `unit piece task job_tag host start_utc deadline_epoch need_s end_source end_epoch`.
- `<JOB_TAG>.end`: `unit rc outcome wall_s cli_status cli_skipped end_utc`, where `outcome` ∈ `ok` (rc 0), `skipped` (rc 0 and the CLI reported an already valid unit), `unit_failed` (rc ≠ 0, not a timeout), `killed_timeout` (rc 124 or 137 from `timeout`). `cli_status` = the `status=` field (SMC: the `v3_status=` field too) parsed from the CLI's last stdout line; `NA` for enum.
- `<JOB_TAG>.deferred`: `unit reason now_epoch deadline_epoch need_s end_source end_epoch`.
A unit with `.start` and no `.end` under the same JOB_TAG was killed from outside (Slurm TIMEOUT, NODE_FAIL, OOM, cancel).

Task inventory: at the end of the task (also on `EXIT` trap, best effort) `LOG_RUN/inventory/<piece>/<JOB_TAG>.tsv` (atomic) with one row per unit of the task: `unit outcome` (`ok skipped unit_failed killed_timeout deferred not_reached`). The ledger is authoritative; the inventory is a convenience.

Task exit status: 0 if no unit `unit_failed`/`killed_timeout` (deferred units are not failures); 1 otherwise (so the waiter wakes OPS). A task that cannot start (missing GNU time for a sizing arm, hook set, frozen mismatch) keeps the pilot exit codes (68, 70, 67, 64–66).

Local-test hooks (refused outside `--local-test`, exactly like the pilot's): `PILOT_DRYRUN`, `PILOT_SKIP_MODULES`, `PILOT_TIME_BIN`, plus `PRODL_UNIT_CMD` (replaces the unit command, for deadline tests), `PRODL_TEST_WALL_S`, `PRODL_TEST_BUDGET_S`, `PRODL_TEST_NOW_OFFSET_S` (adds to `now`, to simulate elapsed time). All are in the hook list of `common.sh` and of the driver.

## 4. Resubmission (D47.2): `B/make_resubmit.sh` and waves

`bash make_resubmit.sh STAMP PIECE WAVE [--dry-run]` (on NOTS, login node, `nice -n 19`):
1. Refuses (exit 3) unless EVERY job id in `RUN_HOME/JOBIDS.tsv` is out of `squeue` and terminal in `sacct` (any scheduler error: exit 4; fail closed).
2. For every expected unit of PIECE (from `lists/units.tsv`): DONE only if the shared strict verifier `prodl_verify.py` accepts the exact file set, hashes, marker and SMC CSV shape; else NOT DONE. SMC prefix `SMCBVS` or `SMCBVS_rep<m>`; enum prefix `EXACT`.
3. Attempts per NOT-DONE unit = number of `.start` ledger records. A unit with ≥ 2 started attempts and no `.done` is an EXCEPTION (`resubmit/<PIECE>_<WAVE>_exceptions.tsv`, reported to HQ, never resubmitted again). Deferred-only units (never started) are always resubmitted.
4. Writes `RUN_HOME/resubmit/<PIECE>_<WAVE>.tsv` in `units.tsv` format, tasks renumbered 0..k−1 in chunks of ≤ 25 (one unit per task for `p5`), sorted by original (task, unit). Idempotent: if the file exists with identical content, exit 0 ("SAME_LIST"); if different, exit 2 (new WAVE name needed). Empty list: writes nothing, prints `NOTHING_TO_RESUBMIT`, exit 0.
5. If stale `*.lock` directories or `*.tmp*` files exist for the listed units, it refuses (exit 5) and names `clear_stale.sh`.

`bash clear_stale.sh STAMP [--yes]`: same terminal-state gate; `stale_lib.sh` finds `*.lock` directories and `*.tmp*` files under this run's result folders; dry run lists them; `--yes` MOVES (never deletes) each with its `owner.txt` to `LOG_RUN/cleanup/<utc>/` and writes a listing.

Waves: `main`, then `r1`, `r2`, …, then `p5` and, if necessary, `p5r1`, `p5r2`, …. A wave is submitted only when no job of the run is active and truth trees are open. Each fitting wave has its own truth-lock test → lock → arrays → unlock → collect chain. The run id of a resubmitted unit is the original piece's run id.

## 7. Throttles and CPU ceilings (D47.4; Sol finding 6): `B/ceiling_check.py`

Python 3.9 stdlib. Billed CPUs of a request of c CPUs = `2 * ceil(c / 2)` (a 1-CPU request bills as 2).

Inputs: `--profile alone|withH`, `--plan <plan.tsv>` (rows: step, cpus, max_concurrent_tasks, phase), `--squeue <file or ->` (output of `squeue -h -u fb31 -o '%i|%j|%T|%C'`; the driver captures it and refuses on a nonzero exit), `--own-ids` (ids of this run, ignored as "others"), `--receipt <file>`.

- PROD-L peak = max over phases of the sum over the phase's steps of `billed(cpus) × max_concurrent_tasks`. Phases of the main wave: `pre` (steps 1–4), `fit` (5, 6, and the larger of 7/8, which never overlap: 8 is afterany 7), `post` (9, 10). Alone: 4 + 4·16 + 32·2 = **132**; withH: 4 + 2·16 + 16·2 = **68**.
- Others' potential peak: over all rows not of this run: a running row counts `billed(%C)`; a pending array row `<id>_[<range>%N]` counts `billed(%C) × max(0, min(n_pending, N − running_of_that_array))` (no `%N`: `n_pending`); a pending plain job counts `billed(%C)`. Unparsable row: refuse.
- PROD-H present = any row whose name contains `_prodH`.
- Refuse (exit 2, reason in the receipt) if: profile `alone` and PROD-H present; PROD-L peak > 132 (alone) or > 68 (withH); others' peak + PROD-L peak > 192. Receipt: every number used. Exit 0 = admitted.

`B/retune_throttle.sh STAMP --profile alone|withH [--yes]`: recomputes the throttles of THIS run's live arrays from `JOBIDS.tsv` and applies `scontrol update JobId=<id> ArrayTaskThrottle=<n>` (dry run by default); never touches another job. Used when PROD-H starts or ends during PROD-L.

## 12. Interface conventions (manager ruling, binding for builder and tester)

- `prodl.env` (written by the manager) is the single source of every path, limit, ceiling and per-piece constant; scripts read `WALL_<piece>`, `BUDGET_<piece>`, `CPUS_<piece>`, `MEM_<piece>`, `THREADS_<piece>`, `THR_A_<piece>`, `THR_H_<piece>`, `RUNID_<piece>`, `CEIL_*`, `START_SLACK_S`, `KILL_GRACE_S`, `COMMIT_MARGIN_S`, `SMC_MEM_GB`, `SMC_HOURS`, `PLANNED_HOME_MB_MAIN|WAVE` from it. `slurm/common.sh` is the pilot's, with the PROD-L hooks added (manager-edited; do not change it without the manager).
- Staged layout: the bundle runs from `HOME_ROOT/runs/<RID>/code/prod_l/`; every script finds `prodl.env` as `$HOME_ROOT/runs/${STAMP}_lowp_prodL/code/prod_l/prodl.env` (sbatch scripts, like the pilot's) or relative to its own location (driver and OPS scripts).
- Scheduler and tool commands are overridable by environment variables (pilot convention): `SBATCH SQUEUE SACCT SCANCEL SCONTROL PYTHON` (defaults `sbatch squeue sacct scancel scontrol python3`), and `GUARD`. Local tests put stubs on PATH as well.
- `ceiling_check.py --plan` files are tab-separated with the header `step cpus max_concurrent_tasks phase`; `--own-ids` is comma-separated; an EMPTY squeue capture is an empty file (no blank line); a blank line is ignored, not an error. Squeue rows are `id|name|state|cpus`.
- `batch_runner.sh` is sourced by the sbatch scripts after `pilot_init`, `pilot_modules`, `pilot_blas_single` (and `pilot_require_frozen` for SMC); it may `exit`. Every sbatch script sets `PRODL_T0=$(date +%s)` as its first command after `set -euo pipefail`.
