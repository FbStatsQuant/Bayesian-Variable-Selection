## I1 (class i): no eligible P5 unit can be missed, whenever its primary completed
1. **Expected inventory is append-only and can be extended from ANY successful scan phase.** `make_p5_list.sh STAMP --from-scan <phase>` accepts any phase with `scan_<phase>.ok` (initial, rN, finalN). If `expected.tsv` does not exist it is created (this also removes II1's promotion procedure). If it exists, rows for newly eligible units (primary native `resource_limit`, `eligible == TRUE`, not already listed) are APPENDED; existing rows are never removed or reordered. Every use appends a line to `RUN_HOME/p5/expected_history.tsv` (`utc phase scan_smc_sha256 scan_smcrep_sha256 rows_before rows_after`). The existing refusals (locked / incomplete / invalid_inspect on a resource_limit row) apply to every phase. Idempotent: the same phase twice adds nothing.
2. **Closure of smc / smcrep** (`make_manifests.sh`) requires a FINAL scan phase (`final*`) that (a) succeeded (`.ok`), (b) has a job id greater than EVERY fitting job id of the run (`s1_`–`s4_` of all waves, not only P5 waves), and (c) passes a **coverage check** against the piece: every unit that reconcile reports `done` for the piece appears as a row of the final scan table (by case_id + repeat_m), the scan has no row for a unit reconcile does not report done, and EVERY final-scan row with primary `resource_limit` is in `expected.tsv`. Any `resource_limit` row with `retry_state` locked / incomplete / invalid_inspect refuses. Any violation → exit 6 (with the list) unless `--allow-incomplete`; a missing/old final scan is exit 6 too. This holds for zero-expected runs (no shortcut through `scan_initial.ok` any more).
3. **Reconcile** reads the newest successful scan phase (highest recorded job id among `scan_*.ok` phases) and reports every `resource_limit` primary that is NOT in `expected.tsv` as an exception of kind `p5_unlisted_eligible` (nonzero exit), and states in INVENTORY.md which scan phase the P5 check used.
4. Late `rN` fitting waves for smc/smcrep stay allowed (needed for recovery); the closure gate above makes them safe. JOB.md §5 P5 step: after ANY fitting wave that follows the initial scan, run a new scan phase and `make_p5_list.sh --from-scan <phase>` again, then P5 waves for new units, then the final scan.
Tests: Sol's `repro_r2_late_complete_scan.sh` and `repro_r2.sh` (in `<PC_TEMP_PATH>`) as regressions: empty initial → late resource_limit primary in r1 → final scan eligible → reconcile nonzero, closure exit 6; the same with a nonempty initial list plus one later eligible unit; extension from the later phase appends exactly that unit (history line written) and, after its P5 retry is done and a newer final scan, closure succeeds; zero-eligible unchanged control (final scan required and sufficient); coverage violations (a done unit missing from the final scan; a final scan older than the last rN job).

## I2 (class i): unexpected outputs and exceptions are per piece, and survive closing
1. `reconcile_prodl.py` writes `<out>/exceptions.tsv` (header `piece kind item detail`; kinds: `unexpected_output`, `malformed_record`, `p5_unlisted_eligible`, `p5_unsafe_state`, plus any other exception it reports) covering live AND closed pieces. INVENTORY.md gets a STATUS line: `CLEAN` (exit 0: all expected units done, P5 complete, no exception), `COMPLETE WITH n HQ-ACKNOWLEDGED EXCEPTIONS` (exit 4: everything done, the only exceptions are acknowledged ones), or `INCOMPLETE OR UNRESOLVED` (exit 1). Exit 2 stays for input errors / tampering.
2. `make_manifests.sh --piece P` refuses (exit 6) if `exceptions.tsv` has any row for piece P, unless `--allow-incomplete` (HQ acknowledged). On closing it saves the piece's exception rows to `RUN_HOME/manifests/<piece>.exceptions.tsv` (also when empty: header only) and records its sha256 in CLOSED (`exceptions_sha256=`, `acknowledged_exceptions=<n>`). An unrelated unfinished piece does not block closing a clean piece (keep accepting reconcile exits 0/1/4 there).
3. Reconcile, for a CLOSED piece, loads and hash-verifies `<piece>.exceptions.tsv` and reports its rows as acknowledged exceptions (kind kept, `acknowledged=yes` in the detail); acknowledged exceptions never disappear and never give exit 0.
Tests: unexpected output with every expected unit done → closure refused; unrelated unfinished piece → clean piece still closes; close with `--allow-incomplete` → move away → reconcile lists the acknowledged exception and exits 4 (not 0); tampered exceptions file → exit 2.
