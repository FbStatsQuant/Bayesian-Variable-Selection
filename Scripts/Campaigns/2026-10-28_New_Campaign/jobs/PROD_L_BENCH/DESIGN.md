Derived from `jobs/PROD_L` (reviewed, READY; its `DESIGN.md` §0–§12 apply unless changed here). `CAMP` = the campaign folder; `B` = `CAMP/jobs/PROD_L_BENCH`; `PL` = `CAMP/jobs/PROD_L`. D38 approval-safe tooling and the local cap of **≤ 8 concurrent R processes** apply to every agent.

## 0. What and why a sibling bundle
The 8 primary benchmark methods (F1–F5, A1–A3) with their committed low-p rules (`code/bench_lowp/ADAPTATIONS.md`, LA-1–LA-4) on the 1,200 sealed low-p datasets × c ∈ {c100, c050} = **2,400 cases**, using the frozen `code/bench_lowp` (r2 manifest `code/bench_v2/lowp_port/BENCH_LOWP_MANIFEST_SHA256_r2.txt`, sha256 `85a18248…a6b7`, 34 files; the live tree matches it exactly with no extra file). A sibling bundle, because PROD_L is reviewed and being submitted: its staged scripts must not change.

## 1. Run identity and layout
- STAMP as in PROD-L; run folder `HOME_ROOT/runs/<STAMP>_lowp_bench` (RID); logs `SCR_ROOT/logs/<RID>`; ONE result folder `SCR_ROOT/results/<STAMP>_lowp_benchres/p0020|p0030/<dataset>_<scale>/<M>.{rds,csv,sha256,done}` (M ∈ F1..F5, A1..A3; written by the frozen CLI). Job names `lowpB_<step>`. Caches/TMP `SCR_ROOT/runs/<RID>_{cache,tmp}`.
- **No truth on NOTS.** The stage holds `code/bench_lowp` (r2 tree) + `code/bench_lowp.SHA256SUMS` (copy of the r2 manifest), `code/prod_l_bench` (this bundle, without tests/review/notes), `code/lowp/R/` is NOT needed, and `study/` = `manifests/inputs_manifest_lowp.csv` + `inputs/p0020|p0030` (1,200 files). NO `truth/`, NO `truth_manifest_lowp.csv`, NO `dev/`. Staging and submission refuse any path component named `truth`/`holdout` (case-insensitive) under the run folder. ## 3. Unit command, budget, retry
- Command: `Rscript $BENCH_DIR/run_bench_case.R --study $STUDY --outroot $SCR_ROOT --run-id <STAMP>_lowp_benchres --case <dataset> --scale <scale> --methods all --library $R_LIBS_BENCH --threads-check` under `MODULES_BENCH` (R 4.5.2, pinned read-only library `/projects/ml75/fb31/BVS/bench20261019/lib/R452`, `R_LIBS_USER` non-existent), single-threaded BLAS.
- CLI exit codes: 0 all rules ok/warning; **2 = a committed scientific failure of some rule (valid record) → outcome `ok`, `cli_status=failed_rules`**, never resubmitted; 1 = infrastructure/input refusal → `unit_failed`; 124/137 = `killed_timeout`. The CLI resumes per method (completed methods are skipped after identity checks).
- Deadline rule exactly as PROD-L (`batch_runner.sh`, scheduler end time). Pieces: `bench` WALL 3,600 s, BUDGET 600 s per case (typical 28.5 s, p90 30.3 s); `benchretry` (D56: one doubled-time retry) WALL 3,600 s, BUDGET 1,200 s; RUNID of both = `<STAMP>_lowp_benchres`.
- 1 CPU (billed 2), `--mem=1G` (pilot peak 256 MiB), `--no-requeue`, Sapphire Rapids, commons.

## 4. Waves, gates, ceiling

No lock/unlock steps.
- Later waves `rN`: `s1_bench` and/or `s2_benchretry` arrays from `RUN_HOME/resubmit/<piece>_rN.tsv` + `s9_collect`.
- Driver `submit_bench.sh --wave main|rN --profile alone|withH [--pieces …] [--dry-run] [--local-test]`: PROD-L's order of checks minus the truth-lock step, plus: (a) the no-truth check; (b) **refuse while any PROD-L fitting job (`lowpL_s[1-4]_*`) is queued or running** (sizing §4: benchmarks are serialized after the SMC/repeat lane), unless `--allow-concurrent-prodl` (HQ only; recorded); (c) `ceiling_check.py` (PROD-L's, unchanged) with this run's plan: alone peak 64, withH 32, others (PROD-H, PROD-L, BENCH_F3, anything of fb31) counted; combined ≤ 192. PROD-H's ≤ 100-array-task guard counts `%32`/`%16`.
- `retune_throttle.sh`, `waiter.sh` (prefix `lowpB_`), `final_accounting.sh`, `cleanup_bench.sh` (B3, receipt), `make_manifests.sh` (`--piece bench|logs`), `reconcile_bench.py`, `make_resubmit.sh`, `clear_stale.sh`: as PROD-L, adapted (no P5, no truth, no enum/smc).

## 5. Completion, resubmission, stale artefacts
- **Case done** iff ALL 8 methods M have a valid unit: `<M>.sha256` exactly two lines `<64 hex>  <M>.rds` and `<64 hex>  <M>.csv` (basenames, no duplicates), both files non-empty and matching; `<M>.done` first line starts `status `; the CSV parses with columns `rule_id role status method_id case_id`, ≥ 1 row, every `status` ∈ {ok, warning, failed}, `method_id == M`, `case_id == <case>`. Shared validator `bench_verify.py` (used by reconcile and make_resubmit). A committed failed rule stays `done` (its rule status is reported).
- **Stale artefacts** (`stale_lib.sh`, bench version): directories `*.lock`; hidden temp files written by the CLI's `atomic()` (`tempfile(".<basename>")` → names starting with `.<M>.rds`, `.<M>.csv`, `.<M>.sha256`, `.<M>.done`); and **incomplete method units** (`<M>.rds`/`<M>.csv`/`<M>.sha256` present without `<M>.done`, which the CLI refuses as "manual repair"). `clear_stale.sh` moves all three kinds (never deletes) to `LOG_RUN/cleanup/<utc>/` after the terminal gate; `make_resubmit.sh` and `make_manifests.sh` refuse while any exists.
- **Resubmission** `make_resubmit.sh STAMP rN` (one call per round; terminal gate as PROD-L): for each case not done, from its ledger history over `bench` and `benchretry`: never started (deferred / not reached / never submitted) → `bench_rN.tsv`; exactly one start, ended `unit_failed` or `killed_external` → `bench_rN.tsv` (one rerun); exactly one start, ended `killed_timeout` → `benchretry_rN.tsv` (doubled budget, once); anything else (≥ 2 starts, or a benchretry attempt already made) → `bench_rN_exceptions.tsv` (HQ). Same idempotence rules and exit codes as PROD-L (SAME_LIST / 2 / NOTHING_TO_RESUBMIT; 5 on stale artefacts). Then ONE `submit_bench.sh --wave rN --pieces <pieces with a list>`.

## 6. Reconcile, close, accept
- `reconcile_bench.py STAMP` (stdlib, `-I`-safe): 2,400 expected cases → `done / deferred / unit_failed / killed_timeout / killed_external / not_run` (ledger of both pieces, by case), `exceptions.tsv` (`piece kind item detail`: unexpected_output, malformed_record, partial_case), rule-status table per method (ok / warning / failed rule rows, from the CSVs, or from the hash-verified closed inventory), STATUS line and exits 0 CLEAN / 4 COMPLETE WITH n HQ-ACKNOWLEDGED EXCEPTIONS / 1 / 2 (as PROD-L R2).
- `make_manifests.sh STAMP --piece bench [--allow-incomplete]` then `--piece logs`: PROD-L's per-piece CLOSED flow (inventory + exceptions snapshots, hash-bound; refusal while exceptions or non-done cases), minus P5 gates.
- **Laptop acceptance after download** `accept_bench.R --results <downloaded results folder> --lists <units.tsv> --code <code/bench_lowp> --r2-manifest <r2 manifest> --inputs-manifest <sealed inputs manifest> --out <dir> [--local-test]` (single R process; reads RDS, the sealed INPUTS manifest and the frozen code; no truth). Revised after Sol R1 (I1–I4): every check is against an authoritative source, never learned from the records: (I1) the exact ordered `(rule_id, role)` sequence = frozen registry + the deterministic structure of `lowp_derive` (F1–F5 cap rules secondary; F4/F5 append the K37 aliases and `ebic1_lam005` / `sic_smax`); (I2, D42.5) the SPEC coefficient contract per rule (penalized finite with support = the row's; OLS all NA for the F1–F3 CV rules and otherwise finite inside the support), EBIC/K37 pairs, A1–A3 finite beta, A1 PIPs in [0, 1]; (I3) identity, seeds (frozen CLI formulas) and input/X/Y(scale)/fold hashes = the sealed inputs manifest, run id = the results folder; (I4) the supplied code = r2, the runner fingerprint recomputed from `record$code$files` and equal to r2's hashes; unless `--local-test`: R 4.5.2, `test_library` FALSE, pinned library, pinned versions (incl. A3's dependency pins), base/recommended only in R's own library. **D54.3: the ABESS exact size check is NOT performed and is disclosed** in the report. Exit 0 ACCEPTED / 2 FAIL / 3 INCOMPLETE; writes `ACCEPT_BENCH.md` + `accept_bench.csv`.
