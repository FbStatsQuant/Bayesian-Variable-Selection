## Numbered findings

1. **[blocking; code/contract, regression, PATCHES] Wall-clock guard invariance is not established and cannot follow from unchanged RNG.**
   Evidence: `code/core/v2_2/core/cpp/v3_ledger.h:107` invokes the registry synchronously during scoring; `v3_engine.h:336` passes the measured stage duration to the guard; `v3_runtime.h:18–26` bases its decision on elapsed wall time plus operation time. The new counting/allocation work therefore enters quantities read by the existing guard even though no new statistic is explicitly passed to it. Saved counterexamples to unconditional output identity already exist: `conformance/work/regression/logs/r1d.txt:3–4` and `REGRESSION_EVIDENCE.md:54–57` show unequal checkpoints and downstream outputs. Same-version timing variation explains why this is not proof of a statistical regression; it also prevents these results from proving universal guard/status invariance. `PATCHES.md:4,71,107,109` overstate determinism and unchanged stop units.
   Concrete fix: state the defensible guarantee explicitly: no extra draws/direct decision inputs; identical statistical trajectories in the same numerical environment when execution reaches the same operations, with time/memory/provenance exceptions and wall-clock-dependent stops separately disclosed. Retain unmatched-stop results. Use fixed/common stop checkpoints for controlled validation, rather than treating selected matching pairs as proof of identical stop policy outcomes. If the task's literal prohibition on any guard effect remains binding, this code is not conformant until an authorized design addresses observer time; a documentation waiver alone cannot satisfy that prohibition.

2. **[blocking; regression] Default `identical()` is stronger than tolerance comparison but is not a floating-point byte comparator.**
   Evidence: `conformance/work/regression/cmp_lib.R:53–54,74–76`; `REGRESSION.md:15–16`. R's default numeric equality treats positive/negative zero as equal and, by default, collapses distinctions among corresponding NaN representations. Attribute lists are compared with default attribute ordering semantics. Thus the advertised “attributes, names and bytes” guarantee is too strong. The saved mutation self-test covers ordinary value/attribute changes, not these cases (`cmp_selftest.R:6–17`, `logs/cmp_selftest.txt:1–13`).
   Concrete fix: use strict numeric/NaN and attribute-order options (`num.eq = FALSE`, `single.NA = FALSE`, `attrib.as.set = FALSE`) where appropriate, or compare atomic payload bytes with an explicit NA/NaN policy while comparing type and attributes recursively. Add signed-zero, NaN-payload and attribute-order mutations. Check container `typeof()` too: the list branch currently checks only `is.list()` and attributes. Recompare the saved paired fits/records and regenerate certification text. These are statically identified acceptance holes, not newly executed mutation tests.

3. **[blocking; regression] Any extra list entries are accepted, including extra old-output events; additions are not allowlisted.**

An extra final `runtime_guard$checkpoints` entry is accepted even though the report says checkpoint counts are compared (`REGRESSION.md:18`; `REGRESSION_EVIDENCE.md:11`). The self-test only drops a checkpoint (`cmp_selftest.R:13`). Inserting a new named field into an existing non-instrumentation list also passes unless it changes old relative order. `shifted` is informational only. The separate exact checkpoint signature in `r1d.R:3,8,13–14` mitigates this for matched-stop selection, not for the general comparator or completed cases.
   Concrete fix: allow only the explicit v2.2 field additions at their exact permitted container paths. Require unchanged lengths for pre-existing event/model/checkpoint lists and unchanged data-frame columns except explicitly authorized additions. Reject insertion before old elements when enforcing the spec's append rule. Add mutations that append a checkpoint, append a near-tie/local-search event, add an unexpected field, and insert an allowed field in the wrong position. Recompare the saved results; no new fit is needed for this repair.

4. **[should-fix; code] Top-level plain fields violate the explicit append-only ordering requirement.**
   Evidence: `conformance/work/IMPL_SPEC_v2_2.md:10,20`; `core/v3_run.R:167–169`; `core/v3_fit.R:56–59,173` under `code/core/v2_2/`. 5. **[should-fix; code, exported API] Persistent `CalState` retains a raw registry pointer without retaining its owning R external pointer.**
   Evidence: `core/cpp/v3_core.cpp:587–588,605–617` retains `setup_keep` and `runtime_keep`, but merely assigns `XPtr<Registry>(registry).get()` to `led->reg`. A caller can construct a state with a temporary registry, discard the registry binding, then trigger GC before a later pilot/diagnostic call. The state does not keep that registry alive. The normal `v3_fit` path retains `registry` in its live R frame/finish closure, so this is not an observed failure of the supplied production fits.
   Concrete fix: add `RObject registry_keep` to `CalState` and assign the supplied SEXP before saving its raw pointer. Validate a persistent state across forced GC in an isolated copy. The synchronous final-run call has its registry argument live and does not have this persistent-state ownership problem.

6. **[should-fix; code operational limits, PATCHES] Exact-registry memory is unbounded in observed-model count; “≤5 MB at p≤32” is an observation, not a bound.**
   Evidence: `v3_registry.h:6,11,20`; `v3_core.cpp:74–75,84–86`; `core/v3_fit.R:27–32,88`; `PATCHES.md:12,66–68`. Every distinct model is retained whenever retained p≤64, even with `keep_scored_set = FALSE`; that switch only prevents data-frame export. Export adds a sorted key vector and several R columns on top of the map. Memory preflight does not include these new allocations. At p33–64 the registry remains exact even though no scored set is returned. The reported 0.27–4.8 MB registry estimates and ~1–4.8 MB data frames describe these smoke fits, not all possible inputs.
   Concrete fix: document O(M) map memory, O(M log M) export time and additional export/RDS memory, the p33–64 behavior, and what `keep_scored_set` actually disables. Report measured costs as measured. Any future bounded/fallback registry needs an explicit incomplete/approximate label, never a silently complete coverage number, and must not alter existing method guards to enforce the observer's cap under this task. Track allocator/rehash overhead as approximate. Also guard or document the `size_t` to `int` narrowing at `v3_core.cpp:85`; p≤32 does not mathematically imply M≤INT_MAX, although practical memory exhaustion would occur much earlier here.

9. **[should-fix; regression, PATCHES] p30 comparisons are to a truncated reference; neither full-posterior coverage nor global HPM exactness is certified.**
   Evidence: `smoke_lowp/exact_p30_trunc.R:5–9`, its log `:1–3`, and `regression/r3.R:12–14,29–34` under `conformance/work/` correctly use the size≤12 reference. 10. **[should-fix; OUTPUT_FIELDS] `first_stage` is phase-dependent and is not always a bridge stage.**
    Evidence: `conformance/OUTPUT_FIELDS.md:98`; `core/cpp/v3_engine.h:286,324,343,385–392`; `v3_core.cpp:413` under `code/core/v2_2/`. For local search, it is the 1-based scan number, not a bridge stage; the un-emitted centre uses the default zero. For initial draws it is zero; for tables it is 1-based block number; terminal rounds retain the island's final bridge stage. Pilot/diag phase overrides also hide their subphase, so `first_stage` alone does not recover every round/event time.
    Concrete fix: document these cases explicitly. Explain that the compact first-score record omits round, particle, position and phi; “when” means the retained coordinates, not a total chronological event index. Do not change the sampler to fill these omissions under this patch.

11. **[should-fix; OUTPUT_FIELDS] Score counters describe ledger events, not all scorer calls or exclusively final particles.**
    Evidence: `OUTPUT_FIELDS.md:106`; `core/cpp/v3_core.cpp:402–414,431–452,704–718`; `core/v3_run.R:160`. The final ledger freshly ingests table entries again, while inherited-model rescoring updates stores directly without ledger events. Calibration V recomputations also bypass ledger events. Held Gibbs states are logical events without evaluation; cache-evicted re-evaluations add fresh events again. Therefore final `score_counts` includes table ingestion plus final island/local events, excludes calibration's ledger events, and also excludes some actual final rescoring. `fresh` is not simply a distinct-model or universal scorer-call count. Combining calibration and final fresh tables counts replayed table events twice.
    Concrete fix: describe both ledgers by their actual scopes and distinguish logical events, fresh ledger events, distinct registered models, and numerical route/scorer-call counters. Keep `scored$n_distinct` as the union cardinality, not a fresh-counter sum. The R2 union bound is a sanity check, not proof that no scored model is missing.

12. **[should-fix; OUTPUT_FIELDS] Availability, stop and stage descriptions need several precise qualifications.**
    Evidence: `OUTPUT_FIELDS.md:11,56,72,78,80,87–88`; `core/v3_fit.R:64,75–88,118–142`; `core/v3_run.R:97–115`. A preflight resource stop happens before any HPM is available and does not set `hpm_incomplete`; it cannot satisfy the blanket failed-fit HPM assertion. Preflight and escalation-preflight stops normally have no exceeded runtime checkpoint, so this implementation's checkpoint-derived fields, including allocation_seconds, are all NA. Final stage count is the frozen grid's interval count once final settings exist, even when a final island stops early; it is not the total number of stages actually executed. `cut_group_large_any` is logical, not a component count. `memory_bytes_estimate` is an estimate of registry C++ storage, excluding exported data frames and general fit memory. Scored reports are absent on preflight stops and setup numerical failure, not merely exact fits.
    Concrete fix: state these conditions, distinguish planned grid size from executed partial stages, identify preflight/preflight_escalation as the source of allocation details when checkpoints are absent, and give each field its actual type. Say that a scored set is produced by default only on the SMC branch with a successfully created registry and retained p≤32.

13. **[should-fix; PATCHES, timing documentation] Runtime and storage costs are plausible measurements, not zero-cost or universal guarantees.**
    Evidence: `PATCHES.md:11–13,66–67`; `v3_registry.h:12–23`; `v3_core.cpp:84–90`. Every fresh event hashes the model; exact mode additionally probes the map, with first insertions doing allocation and LSE work. Scored-set output sorts all keys and materializes columns; compression/serialization also costs time. A single concurrent p500 pair (3172 versus 3216 seconds) cannot isolate an overhead of “a few seconds per 10^8” or establish “none in runtime.” The ~0.4 GB extrapolation for equal numbers of these p20/p30 compressed sets is reasonable as a scored-set-only estimate, not total campaign RDS storage.
    Concrete fix: call these observed sample sizes and an unisolated end-to-end timing comparison; give the algorithmic costs and remove unsupported quantitative overhead claims. `core/v3_fit.R:56–57` samples peak memory/total time before instrumentation/report/scored-set construction: document that exclusion or move operational measurements after construction (time/memory are allowed exceptions). The independent R3 outer wall measurement includes the export and remains useful.

14. **[note; code] Fresh-event registration, compact types, HLL and LSE are sound for the production fit path, subject to the limits above.**
    Evidence: `core/cpp/v3_registry.h:11–32`; `v3_ledger.h:107`; `v3_engine.h:90–105,385–388`; `v3_core.cpp:402–414,448–452,605–616,704–718`; `core/v3_fit.R:142–166`. The same registry spans calibration/final; table replay and cache-evicted re-scores cannot duplicate exact-map counts/LSE/provenance. Cache hits/held states were registered earlier; un-emitted local centres are existing ledger HPMs; inherited models and V members already came from that shared calibration registry. Thus those bypasses do not omit new models in `v3_fit`. This conclusion does not extend to an arbitrary standalone final call with a newly empty registry and externally supplied inherited models: those bypass the hook.
    Exact masks use shifts only for p≤64 (j≤63), and numeric exported keys are exact through p32, including the high bit. Phase/mechanism/tier fit int8; production islands 0–4 and iter -1/0/1..ell fit int16, since ell is logarithmic in R matrix dimensions; stages already use int-sized budgets and int32 storage. Arbitrary low-level caller integers are not range-checked before narrowing. HLL uses the top14 bits and correct remaining50-bit ranks (zero tail→51), duplicate updates are idempotent, and linear counting is correct. Its nominal relative standard error is approximately 1.04/sqrt(16384), about 0.81%, not a guaranteed ±1% bound. Streaming LSE is correct for finite F, with duplicates excluded before accumulation. Successful nonempty scorer results are finite or throw (`v3_score.h:187,201,227–237`).
    Concrete action: retain the hook; document production-fit versus standalone-registry scope and the statistical HLL error interpretation. If arbitrary low-level registry use is supported, register only the otherwise-unseen inherited models through the observer without adding ledger events, and range-check compact metadata. Do not make repeated scorer calls to validate registry membership in production.

15. **[note; code, OUTPUT_FIELDS, PATCHES P1/P3] Plain PIPs and adapter additions implement the requested definition without extra RNG.**
    Evidence: `core/cpp/v3_engine.h:350–371`; `core/v3_run.R:167–169`; `study/adapter.R:427–430`. Inclusion counts are taken after each complete measured population round, divided by N×Hm (production Hm=4), then pooled equally over four islands. Counts do not alter particle/cache/store state or consume draws. Registry SplitMix64 acts on a local hash accumulator (`v3_registry.h:13–15`, `v3_util.h:36–40`), not sampler RNG state. Optional registry arguments are last and default to R_NilValue (`v3_core.cpp:421,605`); old calls retain their argument interpretation. The changed island-list construction preserves the old stream position. Adapter plain PIPs correctly expand named retained original indices into a length-original-p vector with dropped columns zero and all-NA when unavailable. `record["mpm_plain"] <- list(NULL)` preserves a named NULL entry; `$mpm_plain <- NULL` would remove it. No CSV-schema/row construction changes appear in the diff; saved `logs/r1e.txt:1–15` supports the same ordered schema and only timing/provenance cell differences, not raw CSV byte identity.
    Concrete action: retain this implementation while fixing top-level ordering. Keep OUTPUT_FIELDS' retained-bit key convention (`:91`) and full-scale coverage formula (`:84`): these are correct. Truth lookup must first map original support through preprocessing$kept; it is not generally sum(2^(original_j-1)) after dropped columns.

16. **[should-fix; PATCHES recommendations] Keep the P3/P4/P5/P6 directions, with narrower claims and explicit readiness gates.**
    Evidence: `PATCHES.md:70–76,78–118,120–147`. Truth-free post hoc scored-set lookup is sound. Replay can recover watched first events without influencing proposals, but reproducibility requires the same code, preprocessing, numerical environment and operations reached; allocation/wall timing determine termination. P6 demonstrates a useful smoke, not campaign-wide readiness: two smoke datasets with three method seeds each, no escalation, p30 truncated reference, and the low-p adapter/runner still pending.
    Concrete fix: retain the policy proposals, qualify replay/common-prefix statements, label historical counts as supplied background (the underlying historical runs are outside this review's authorized paths), and keep full-reference/adapter/runner/production-platform validation gates visible. Define NON-BEHAVIOURAL as statistical observer behavior with the explicit exceptions in finding 1, rather than promising literally unchanged time/guard outcomes. P4 remains reporting-only only while it does not feed diag_flag, selection, retries or guards. No benchmark/campaign findings beyond the provided evidence were independently verified here.
