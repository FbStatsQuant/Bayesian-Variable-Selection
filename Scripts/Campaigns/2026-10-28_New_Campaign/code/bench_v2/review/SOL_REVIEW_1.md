## Numbered findings and exact fixes

### R1-1 — BLOCKING, class (i): the shared bundle validator can accept missing or wrong scientific evidence

**Evidence.** `bench_audit/jobs/BENCH_F3_PROD/runner/validate.R:3`–24 checks six IDs, schema number, a few row fields, and successful penalized support. It does not check `beta_ols`, coefficient index/lambda/k/alpha, failed-rule audit vectors, registry roles, vocabulary, pilot/screen diagnostics, or most CSV/RDS equality. Its positive test deliberately contains no OLS vectors or pilot evidence (`tests/test_validator.R:4`–10). `runner/reconcile.py:36`–45 binds CSV run/case/source but never binds input hashes/seeds to the frozen input manifest; `:87` delegates RDS acceptance to this weak validator. `runner/task.sh:21` uses it in every task. DEV explicitly uses this same sibling runner (`BENCH_F3_DEV/JOB.md:3`).

**Independent reproduction.** On the actual six-rule runner RDS, each of ten separate corruptions was accepted: removed EBIC OLS vector; impossible coefficient index; k=999; deleted pilot diagnostics; retired `kappa_edge`; wrong primary role; zeroed input SHA-256; doubled nonzero coefficient values; wrong CSV criterion; and an infinite failed-rule audit vector. See `review/sol_scripts/check_saved.R`'s final block and `check_saved.log`, `BUNDLE_VALIDATOR_CORRUPTION ... accepted TRUE`. These are counterexamples to the claimed schema-v2/coefficient acceptance gate, not observed production corruptions.

**Exact fix.** Use one full v2 validator for task and reconciliation, incorporating the frozen wrapper validator's schema/role/vocabulary/metadata/failure checks (`code/bench_v2/F3_AdaptiveLasso/tests/validate_outputs.R:9`–138), rather than maintaining this reduced substitute. Bind each expected case to the appropriate frozen manifest: dataset, p/scenario/replicate/scale, input/X/y/fold hashes and seeds, and compare corresponding CSV/RDS case/provenance fields. Validate both coefficient copies; length/finiteness/status/support/audit/index/lambda/alpha; NA conventions for whole-fit and CV OLS evidence; finite EBIC OLS slopes, zero off support and their RSS. Validate pilot/keep/weights/null/singleton evidence. Check selected penalized coefficients against the saved lambda/weights on the consumed input (selected-point KKT), so changing coefficient values while preserving support cannot pass. Add a complete real-record positive fixture and corruption controls for these fields; all ten reproductions above must fail for the intended reason. Re-run task and full-reconciliation integration against the actual freeze, preserving the new runner bundle manifest. No fitting-code change is indicated by this finding.

### R1-2 — SHOULD-FIX, class (i): several advertised negative controls do not exercise a broken implementation

**Evidence.** `code/bench_v2/tests/run_all_tests.R:47`–52 computes the correct rank-deficient candidate, edits `valid`, then asserts the edited value is false. `:57`–61 computes an alternative ordering outside `ebic_pick`. `:66`–70 edits a correctly rejected RSS score. `:183`–185 removes the injected KKT fault and asks the now-correct output to remain failed. **Exact fix.** Add isolated function mutations that (1) remove the rank gate, (2) allow nonpositive/nonfinite RSS to obtain a finite score, (3) reverse the actual `ebic_pick` key tie order, and (4) bypass the actual selected second-stage KKT failure condition while leaving the injected fault present. Keep the current five genuine mutations and the deployed-ridge canary. Changes outside frozen fitting sources can be confined to the test harness; ledger any changed manifest member.

### R1-3 — SHOULD-FIX, class (ii): staging changes upload membership, and upload-folder verification needs a separate documented path

Add a real-freeze prepare → simulated stage → repeat verification test and a download-manifest round trip. Do not weaken exact-membership verification or the terminal-job checks to make this pass.
